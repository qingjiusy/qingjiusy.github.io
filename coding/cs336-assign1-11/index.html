CS336 Assignment 1 · 交互式学习笔记本

分词器（Tokenizer）是整条流水线的入口：它把人类的文本变成模型能吃的一串整数 id，再把 id 变回文本。本作业用的是 字节级 BPE（Byte-level Byte-Pair Encoding），也就是 GPT-2 系列用的方案。这一章帮你建立三件事的直觉：字节表示、BPE 训练在数什么/合并什么、以及编码/解码的数据流——最后给出带步骤注释的骨架让你自己写实现。

学习目标
#

  1. 理解字节级表示：任意文本 → UTF-8 字节 → 0–255 的整数序列，为什么"没有 OOV"。
  2. 看懂 gpt2_bytes_to_unicode 这套"字节↔可打印字符"映射，从而能读懂序列化后的 vocab / merges 文件。
  3. 用文字讲清 BPE 训练：从 256 个字节 token 起步，反复"统计相邻 pair 频率 → 合并最高频对 → 直到 vocab_size"，以及决定胜负的 tie-break 规则。
  4. 检查已训练好的参考产物（reference vocab / merges），直观看到"训练输出"长什么样。
  5. 理解编码/解码的数据流，并拿到 train_bpe 与 Tokenizer 的引导骨架。

⚠️ 学术诚信（本章尤其严格）：BPE 训练循环和 encode 的合并循环是本作业的核心考点，本笔记本绝不实现它们。下面的代码只做两类安全的事：(a)表示层演示（字节、映射、正则预分词边界的展示）；(b)检查已训练好的参考产物（加载 fixtures 打印出来看）。真正的算法只用文字讲清，实现处给 ... 留白的引导骨架。这里不会出现"我的输出 == 参考输出"这种对拍 cell——那是你自己写完实现后用 pytest 去验证的。

Part A · 字节级表示：一切文本都是 0–255 的整数
#

字节级 BPE 的地基是一个朴素的事实：任何字符串都能被 UTF-8 编码成一串字节，每个字节就是一个 0–255 的整数。这带来一个关键性质——没有 OOV（out-of-vocabulary）：哪怕遇到训练时从没见过的字、emoji、乱码，也总能拆成字节表示出来。代价是一个多字节字符（如中文、emoji）会占好几个字节。

下面把一段中英混合文本编码成字节看看。注意 ASCII 字符占 1 个字节，而"世"这类字符占 3 个字节。

s = "hello 世界 🙃"
b = s.encode("utf-8")

print("原始字符串 :", s)
print("字符数 len(s)      :", len(s))
print("UTF-8 字节数 len(b):", len(b))
print("每个字节都是 0-255 的整数:")
print(list(b))

print("\n逐字符看它占几个字节:")
for ch in s:
    print(f"  {ch!r:>6} -> {list(ch.encode('utf-8'))}")

print("\n=> 字节表能覆盖任意文本，所以字节级 BPE 永远不会遇到 OOV。")

Part B · 字节 ↔ 可打印字符的映射
#

字节里有很多不可打印的值（空格、换行、控制字符），直接写进文件里既难看又容易和分隔符冲突。GPT-2 用一套固定的双射映射把 256 个字节各自映到一个可打印的 Unicode 字符，这样 vocab / merges 文件就能是纯文本、方便肉眼检查。tests/common.py 里的 gpt2_bytes_to_unicode() 就是这套映射。

最典型的例子：空格 chr(32) → 'Ġ'、换行 chr(10) → 'Ċ'。所以你在 merges 文件里看到的 Ġ t，其实代表"（空格）“这个字节和 t 这个字节。理解这一点，才能读懂后面打印出来的参考产物。

b2u = gpt2_bytes_to_unicode()   # {0..255: 可打印字符}

print("\n关键: 空格 32 ->", repr(b2u[32]), " 换行 10 ->", repr(b2u[10]))
print("所以 merges 文件里的一行 'Ġ t' 表示: (空格字节) 和 (字母 t) 这两个 token 被合并。")

Part C · BPE 训练在做什么（只讲算法，不写代码）
#

BPE 训练的目标是：从最基础的字节起步，学出一批"高频组合"作为新 token，直到词表达到指定大小 vocab_size。核心循环用一句话概括就是——反复"数相邻对、合并最高频的那一对”。

初始状态

  • 词表先放入 256 个单字节 token，再加上若干特殊 token（如 <|endoftext|>）。
  • 语料先做预分词（pre-tokenization，见 Part D），每个 pre-token 变成一串字节 token。

重复以下步骤，直到 len(vocab) == vocab_size：

  1. 统计当前所有序列里相邻 token 对（bigram）的出现频率。
  2. 选出频率最高的那一对。若多个对并列最高，用 handout 规定的 tie-break 规则打破平局（例如按对应字节序比较，取"较大"的那一对——务必以 handout 为准，这一步选错，你的 merges 顺序就会和参考答案对不上）。
  3. 把这一对记录为一条 merge（记录顺序 = 合并的先后顺序），并在词表里新增这个合并后的 token。
  4. 在所有序列里把这一对相邻 token 替换成新 token，然后回到第 1 步。

输出两样东西

  • vocab: dict[int, bytes]，token id → token 的字节内容。
  • merges: list[tuple[bytes, bytes]]，按创建顺序排列的合并规则。

直觉：高频的字母组合（如 t+he → the）会先被合并成一个 token，于是常见词只需很少的 token 就能表示，而罕见串仍可退回到字节，两全其美。

🖐️ 纸面手推（放这里体会，别用代码去实现这个循环）
#

拿一个玩具"语料"：只有一个词 low，出现了 5 次（真实训练里当然是整篇文本，这里极简化）。初始每个 pre-token 是字节序列 l o w。

轮次 当前序列 相邻对计数 最高频对 新 merge
1 l o w ×5 (l,o)=5, (o,w)=5 平局 → 按 tie-break 选 记作 merge #1，假设选 (o,w)→ow
2 l ow ×5 (l,ow)=5 (l,ow) merge #2：(l,ow)→low

两轮后词表新增了 ow、low 两个 token。注意第 1 轮的平局：真实语料里平局非常常见，所以 tie-break 规则不是细节而是正确性关键——它直接决定 merges 的顺序，而测试是逐条比对顺序的。

练习：把语料换成 low×5 + lower×2，自己在纸上多推两轮，感受计数如何随合并变化。不要写代码实现这个循环——那是作业本体。

Part D · 预分词（pre-tokenization）：先切成"词块"再谈合并
#

如果直接在整段文本的字节流上做 BPE，合并会跨越词边界甚至跨越空格，学出一些奇怪的 token。GPT-2 的做法是先用一个正则表达式把文本切成"预分词块"（大致是"词 / 标点 / 带前导空格的词"），BPE 合并只在每个块内部进行，不跨块。

  • 这个正则由 handout 直接给出（GPT-2 的标准 pattern），你不需要自己发明，用 regex 模块（不是标准库 re）来跑它。
  • 处理大文件时，cs336_basics/pretokenization_example.py 提供了 find_chunk_boundaries：在特殊 token（如 <|endoftext|>）处切分文件，方便并行统计各块的 pre-token 计数——特殊 token 是不能被合并"吃掉"的天然边界。

下面只做表示层演示：看一段文本被切成哪些块。注意每个块常常带一个前导空格（映射后就是那个 Ġ），以及标点会单独成块。这一步不是 BPE 合并，只是把文本切成待处理的小段。

import regex as re

GPT2_PAT = r"'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"

sample = "the cat sat on the mat. It's low-cost!"
pre_tokens = re.findall(GPT2_PAT, sample)

print("原文:", repr(sample))
print("预分词后的 pre-token (共 %d 个):" % len(pre_tokens))

for pre_token in pre_tokens:

Part E · 检查已训练好的参考产物

# 逆映射: 可打印字符 -> 原始字节整数 (与 tests 中的做法一致)
byte_decoder = {v: k for k, v in b2u.items()}

def load_ref_vocab(path):
    raw = json.load(open(path))                      # {可打印字符串: id}
    return {idx: bytes(byte_decoder[c] for c in tok) # -> {id: bytes}
            for tok, idx in raw.items()}

def load_ref_merges(path):
    out = []
    with open(path, encoding="utf-8") as f:
        for line in f:
            parts = line.rstrip().split(" ")
            if len(parts) == 2:
                a, b = parts
                out.append((bytes(byte_decoder[c] for c in a),
                            bytes(byte_decoder[c] for c in b)))
    return out

vocab = load_ref_vocab(FIX / "train-bpe-reference-vocab.json")

Part F · 编码 / 解码的数据流（讲清方向，实现留给你）
#

有了 vocab 和 merges，Tokenizer 做两件互逆的事：

encode（文本 → id 列表）

  1. 先把特殊 token 单独抠出来（它们永不被拆分，直接映射到自己的 id）。
  2. 对普通文本做预分词（Part D 的正则），每个 pre-token 变成字节序列。
  3. 在每个 pre-token 内，按 merges 的顺序反复施加合并（谁先在 merges 里出现就先合并谁）——这一步就是 BPE 的"应用"，是本作业的核心考点。
  4. 把最终的字节 token 通过 vocab 的逆查表换成整数 id。
  5. 还要提供 encode_iterable：能对一个行迭代器惰性地产出 id，用于流式处理大文件而不爆内存。

decode（id 列表 → 文本）

  1. 用 vocab 把每个 id 换回它的 bytes。
  2. 把这些 bytes 按顺序拼接成一个大的字节串。
  3. 用 utf-8 解码回字符串（注意：单个 token 可能是"半个"多字节字符，所以要先拼接再解码，且解码要能容错处理非法字节）。

下面只在表示层验证一个直觉——单个 token 的 bytes 未必能独立解码成合法字符，从而理解 decode 为什么必须"先拼接全部、再一次性 utf-8 解码"。这不是 decode 的实现（不做查表+拼接的完整流程），只是观察一个字节片段的性质。

# 表示层观察: 一个多字节字符被拆成的“半个字符”字节，单独解码会失败/乱码
partial = "世".encode("utf-8")[:1]     # 只取“世”的第一个字节
print("“世”的完整 UTF-8 字节:", list("世".encode("utf-8")))
print("只取第一个字节:", list(partial))
try:
    print("单独 strict 解码:", partial.decode("utf-8"))
except UnicodeDecodeError as e:
    print("单独 strict 解码 -> 抛异常:", type(e).__name__)
print("errors='replace' 容错解码:", repr(partial.decode("utf-8", errors="replace")))
print("\n=> 所以 decode 必须先把所有 token 的 bytes 拼起来，再整体 utf-8 解码(并容错)。")

下面是给你填的骨架（... 处留白，不可直接运行出结果）。它只列出步骤思路，不含任何求解行——数 pair、选最高频、应用合并这些必须你自己写。动手前想清楚三件事：

  • 数据结构：pre-token 计数用什么装？为了避免每轮重扫全部文本，能不能维护"每个 pre-token 的当前 token 序列 + 它的出现次数"？
  • tie-break：并列最高频时，严格按 handout 的规则选，否则 merges 顺序会错。先在小 vocab 上和参考产物对拍。
  • 效率：test_train_bpe_speed 要求 corpus.en 在 1.5s 内跑完。朴素每轮重新统计是 O(n²) 级别；想想合并一对后，只有邻近的计数会变。
from collections import defaultdict

def train_bpe(input_path, vocab_size, special_tokens):
    # step 1: 初始化 vocab（一个dict）
    # 先放 256 个单字节 token，再加入 special_tokens
    vocab = {index : bytes([index]) for index in range(256)} #注意这里的bytes([index])写法，不应该写bytes(index)，因为我们是想让index变成单个byte token
    for index, special_token in enumerate(special_tokens):
        vocab[index + 256] = special_token.encode("utf-8")

    # step 2: 读语料 + 预分词，得到 {pre_token(字节序列): 出现次数} 的计数
    #（大文件可用 pretokenization_example.find_chunk_boundaries 在特殊token处切块并行）
    # 读语料
    with open(input_path, "r", encoding="utf-8") as f:
        text = f.read() # text是UTF-8编码的字符串，type是str

    # 在切分语料的时候，为了实现更效率的切分，更好的利用我们的CPU资源，可以使用多进程
    # 多进程切分完成以后，先用special token切分，然后用regex实现正则表达式的切分，我们的text（str）就变成了一个个单词
    # 然后单词的str去调用encode方法，就变成了bytes数组
    # 准备一个记数表（byte-token tuple -> count）去记录每种pretoken的byte序列出现了多少次，用来实现去重
    # 计数表中的例子：(b"h", b"e", b"l", b"l", b"o") -> 5,意思是hello出现了五次
    pretoken = defaultdict(int)

    special_pattern = "|".join(re.escape(tok) for tok in special_tokens)
    if(special_tokens != []):
        parts = re.split(special_pattern, text)
    else:
        parts = [text]

    # 接下来把text的str列表进行regex分割，然后转成bytes tuple并计数
    PAT = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+""" # GPT-2正则
    
    # 统计pretoken的频率,之后用于统计相邻token pair频率
    for part in parts:
        parts_after_re = re.findall(PAT, part)
        for part_after_re in parts_after_re:
            pretoken[tuple(bytes([byte]) for byte in part_after_re.encode("utf-8"))] += 1

    # step 3: 循环，直到 len(vocab) == vocab_size:
    merges = []
    while(len(vocab) < vocab_size):

        # 3a. 统计所有相邻 token 对的频率(按 pretoken 数量加权)，记录在 pair_count 中
        pair_count = defaultdict(int)
        for pretoken_tuple, count in pretoken.items():
            for i in range(len(pretoken_tuple) - 1):
                pair_count[(pretoken_tuple[i], pretoken_tuple[i + 1])] += count

        if(not pair_count):
            break

        # 3b. 选频率最高的对；平局用 handout 的 tie-break 规则，也就是：频率相同时用更大的字典序的
        max_pair = max(pair_count, key=lambda pair: (pair_count[pair], pair))

        # 3c. 记录这条 merge，并把合并后的新 token 加进 vocab
        vocab[len(vocab)] = max_pair[0] + max_pair[1] #max_pair是(b"h",b"e")，vocab中加入的新词应该是b"he"
        merges.append(max_pair)

        # 更新pretoken
        # 遍历每一个pre_token，检查有没有可以合并的bytes
        # 3d. 在每个 new_pretoken 序列里把 max_pair 替换成新 token
        new_pretoken_counts = defaultdict(int)

        for pretoken_tuple, count in pretoken.items():
            new_pretoken = []
            i = 0

            while i < len(pretoken_tuple):
                # 当前 token 和下一个 token 正好组成 max_pair
                if (
                    i < len(pretoken_tuple) - 1
                    and pretoken_tuple[i] == max_pair[0]
                    and pretoken_tuple[i + 1] == max_pair[1]
                ):
                    # 合并两个 bytes token
                    new_pretoken.append(max_pair[0] + max_pair[1])
                    i += 2 # 已经处理了两个 token，所以向后移动两位
                else:
                    # 没有匹配到 max_pair，保留当前 token
                    new_pretoken.append(pretoken_tuple[i])
                    i += 1

            # list 转回 tuple
            new_pretoken_tuple = tuple(new_pretoken)

            # 保留原 pretoken 的出现次数
            new_pretoken_counts[new_pretoken_tuple] += count

        # 用新的统计结果替换旧的 pretoken
        pretoken = new_pretoken_counts
 
    # step 4: 返回 (vocab, merges)
    return vocab, merges

通常这里还可以进行一种优化，就是去并行的切分语料，进行预分词 + 计数

核心思路是：先按文件的 byte offset 切成多个 chunk，并保证 chunk 边界落在 special token 边界附近；每个进程分别读取自己的 chunk、做 regex 预分词、统计局部 pretoken_counts；最后主进程把这些局部计数加起来。

import regex as re
from collections import defaultdict
from concurrent.futures import ProcessPoolExecutor
from cs336_basics.pretokenization_example import find_chunk_boundaries

PAT = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""

def process_chunk(input_path, start, end, special_tokens):
    """
    一个子进程处理 [start, end) 这一段文件。
    返回这个 chunk 内部的 pretoken 频率表。
    """
    local_pretoken = defaultdict(int)

    # 注意这里用 rb，因为 start/end 是 byte offset
    with open(input_path, "rb") as f:
        f.seek(start)
        chunk = f.read(end - start)

    text = chunk.decode("utf-8")

    # 先按 special token 切
    if(special_tokens):
        special_pattern = "|".join(re.escape(tok) for tok in special_tokens)
        parts = re.split(special_pattern, text)
    else:
        parts = [text]

    # 再做 GPT-2 pretokenization
    for part in parts:
        for token in re.findall(PAT, part):
            token_bytes = token.encode("utf-8")

            byte_tuple = tuple(bytes([byte]) for byte in token_bytes)
            local_pretoken[byte_tuple] += 1

    return local_pretoken

def train_bpe(input_path, vocab_size, special_tokens):
    vocab = {i: bytes([i]) for i in range(256)}

    for index, special_token in enumerate(special_tokens):
        vocab[index + 256] = special_token.encode("utf-8")

    # 通过 find_chunk_boundaries 找到了切分成4段的 boundaries
    with open(input_path, "rb") as f:
        boundaries = find_chunk_boundaries(f, 4, b"<|endoftext|>")

    # 保存每个“异步提交出去的任务”
    jobs = []

    # 开一个进程池
    with ProcessPoolExecutor(max_workers=4) as executor:

                # 表示函数 process_chunk 调用下面的四个参数
                executor.submit(

                    input_path,
                    start,
                    end,
                    special_tokens,
                )
            )

    # 合并所有进程的统计结果
    pretoken = defaultdict(int)

    for job in jobs:
        local_counts = job.result()

        for token, count in local_counts.items():
            pretoken[token] += count

    # 之后就和前面一样，开始进行 merge
    # step 3: 循环，直到 len(vocab) == vocab_size:
    merges = []
    while(len(vocab) < vocab_size):

        merges.append(max_pair)

        # 更新pretoken
        # 遍历每一个pre_token，检查有没有可以合并的bytes
        # 3d. 在每个 new_pretoken 序列里把 max_pair 替换成新 token
        new_pretoken_counts = defaultdict(int)

        for pretoken_tuple, count in pretoken.items():
            new_pretoken = []
            i = 0

Part G · ✏️ 你的任务（二）：Tokenizer 引导骨架
#

Tokenizer 需要 encode / encode_iterable / decode 三个方法（参考 handout 与 tests/test_tokenizer.py 里对各种边界情况的测试：空串、单个 unicode 字符、特殊 token、内存上限等）。骨架同样只列步骤，合并循环和查表都留给你写。

  • encode 里的合并：怎样"按 merges 顺序"应用？一个思路是把 merges 的先后做成"优先级"，每步在当前序列里找优先级最高的可合并相邻对并合并，直到没有可合并的对。想清楚终止条件。
  • 特殊 token：要先把它们从文本里切出来（用 re.split 保留分隔符的技巧），避免被当普通文本拆碎；注意有的特殊 token 可能是另一个的前缀。
  • decode 的容错：见 Part F —— 先拼接全部 bytes，再 utf-8 解码并容错。
class Tokenizer:
    def __init__(self, vocab, merges, special_tokens=None):
        # step 1: 存下 vocab / merges / special_tokens
        self.vocab = vocab # id -> bytes
        self.merges = merges # 记录需要合并的 token pair
        self.special_tokens = special_tokens

        # step 2: 预计算好方便查的结构
        # id -> bytes 的逆表，方便 encode 时快速进行
        # bytes -> id
        self.byte_to_id = {token_bytes: token_id for token_id, token_bytes in vocab.items()}

        # merges 的优先级表
        # 找到正确的优先级对应才能正确的进行merge
        self.ranks = {pair: rank for rank, pair in enumerate(merges)}

    def encode(self, text):
        # step 1: 先把 special_tokens 从 text 中切出来(它们直接映射到自己的 id)
        if(self.special_tokens):
            # special token 可能互相重叠，因此优先匹配更长的
            sorted_special_tokens = sorted(self.special_tokens, key=len, reverse=True)

            # 通过加 ( 和 )，变成捕获组
            special_pattern = "(" + "|".join(re.escape(tok) for tok in sorted_special_tokens) + ")"
            parts = re.split(special_pattern, text)
        else:
            parts = [text]

        # step 2: 普通文本段落 -> 预分词(Part D 的正则) -> 每段变字节序列
        PAT = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+""" # GPT-2正则
        ids = []

        for part in parts:
            # 是special_tokens，直接得到对应id
            if(self.special_tokens and part in self.special_tokens):
                ids.append(self.byte_to_id[part.encode("utf-8")])
            else:
                pre_tokens = re.findall(PAT, part)

                for pre_token in pre_tokens:
                    raw_bytes = pre_token.encode("utf-8")
                    byte_tokens = [bytes([b]) for b in raw_bytes]

                    # step 3: 对这个 byte_tokens，按 merges 的优先级反复合并相邻对，直到不能再合并
                    while True:
                        # 找出当前所有相邻 pair
                        pairs = [(byte_tokens[i], byte_tokens[i + 1]) for i in range(len(byte_tokens) - 1)]

                        # 只保留存在于 self.ranks 里的 pair
                        mergeable_pairs = [pair for pair in pairs if pair in self.ranks]

                        # 如果一个都不能合并，就结束
                        if not mergeable_pairs:
                            break

                        # 找优先级最高的 pair
                        best_pair = min(mergeable_pairs, key=lambda pair: self.ranks[pair])

                        # 把当前 byte_tokens 里所有这个 pair 合并
                        i = 0
                        new_byte_tokens = []

                        while(i <= len(byte_tokens) - 1):
                            if(i <= (len(byte_tokens) - 2) and (byte_tokens[i], byte_tokens[i + 1]) == best_pair):
                                new_byte_tokens.append(byte_tokens[i] + byte_tokens[i + 1]) # 两个bytes 可以用 + 来直接合并
                                i += 2
                            else:
                                new_byte_tokens.append(byte_tokens[i])
                                i += 1

                        byte_tokens = new_byte_tokens
        
                    # step 4: 把最终 token 的 bytes 逐个查逆表得到 id，拼成 id 列表返回
                    ids.extend(self.byte_to_id[byte] for byte in byte_tokens)

        return ids

    def encode_iterable(self, iterable):
        # step 1: 对 iterable(如文件的行) 逐段调用 encode 的逻辑，惰性 yield 出 id
        # iterable 是一个储存着一行行文本的数组
        # yield 用于流式处理大文件，避免一次性读入内存
        for text in iterable:
            ids = self.encode(text)

            for id in ids:
                yield id

    def decode(self, ids):
        # step 1: 每个 id -> self.vocab[id] 得到 bytes
        id_bytes = []
        for id in ids:
            id_bytes.append(self.vocab[id])

        # step 2: 把这些 bytes 按顺序拼接成一个大字节串
        byte_str = b"".join(id_bytes)

        # step 3: utf-8 解码(带容错) 得到最终字符串
        # 如果遇到非法 UTF-8 字节序列，不报错，而是用替代字符 � 代替。
        return byte_str.decode("utf-8", errors="replace")

小结
#

  • 字节级表示：文本 → UTF-8 字节 → 0–255 整数，天然无 OOV，代价是多字节字符占多个字节。
  • gpt2_bytes_to_unicode 把字节映到可打印字符（空格→Ġ），让 vocab / merges 文件可读；读产物前先记住这套映射。
  • 训练 = 反复"数相邻对 → 合并最高频对"，直到 vocab_size；tie-break 规则决定 merges 顺序，是正确性关键。
  • 预分词用 handout 给的正则先切块，合并只在块内进行；特殊 token 是天然边界。
  • encode = 预分词 → 按 merges 顺序合并 → 查表得 id；decode = id→bytes→拼接→utf-8 解码。
  • 本章代码只做表示层演示和检查参考产物；训练循环与 encode 合并循环请你在 cs336_basics/ 里亲手实现，用 pytest 对拍验证。
