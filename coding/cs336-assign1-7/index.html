CS336 Assignment 1 · 交互式学习笔记本

前面几章的模块（Linear、Embedding、RMSNorm、注意力打分）都有一个共同的"盲点"：它们看不到 token 的顺序。这一章带你建立 RoPE（Rotary Position Embedding，旋转位置编码） 的直觉——用"旋转"把位置信息注入 Q/K，并且旋转后点积只依赖相对位置。

学习目标
#

  1. 理解为什么需要位置信息：自注意力对输入顺序天生不敏感（置换等变）。
  2. 掌握 RoPE 的核心思想：把特征维两两配对，按 位置 × 频率 的角度做二维旋转。
  3. 看懂频率表 $\text{freq}_i=\theta^{-2i/d}$：不同维度对以不同速率旋转（有快有慢）。
  4. 理解 RoPE 的精髓——旋转后 $q,k$ 的点积只取决于相对位置 $(m-n)$。
  5. 记住工程约定：只对 Q/K 施加，不动 V；位置来自 token_positions 参数。

学术诚信：本笔记本用通用的 2×2 旋转矩阵来演示"旋转"这一几何概念，用来建立直觉——它不是 adapters.py::run_rope 里要交付的那个针对 d_k 的前向实现。频率曲线只是把公式画出来看形状。真正的实现（张量配对、施加到 Q/K、处理任意前导维与 token_positions）留给你，本章结尾只给带步骤注释的骨架，... 处留白。

Part A · 为什么需要位置信息？
#

自注意力靠 query 和 key 的点积来决定"谁关注谁"。但纯内容的点积 $\langle x_i, x_j\rangle$ 只跟两个 token 的向量内容有关，完全不知道它们在序列里的下标 $i,j$。

换句话说：如果你把序列里的 token 重新排列，注意力打分矩阵只是跟着被"置换"，数值本身一个都没变——模型看到的是一个词袋，“猫 追 狗"和"狗 追 猫"在它眼里没有区别。没有位置编码时，不管猫和狗出现在第几个位置，猫对狗的注意力值都一样；模型只能知道“猫和狗同时出现且内容相关”，不知道谁在前、谁在后。下面亲手验证这个置换等变性质。

# 3 个 token 的内容向量（d=4），当作已经算好的 Q（这里 Q=K=内容，仅演示）
torch.manual_seed(7)
X = torch.randn(3, 4)                       # (seq=3, d=4)

scores = X @ X.T                            # 纯内容的点积打分 (3,3)
print("原始打分矩阵 scores =\n", scores)

# 把序列顺序打乱：交换 token 0 和 token 2
perm = torch.tensor([2, 1, 0])
Xp = X[perm]
scores_p = Xp @ Xp.T

# 打乱后的打分，其实就是原打分做同样的行列置换——数值没有任何新信息
same = torch.allclose(scores_p, scores[perm][:, perm], atol=1e-6)
print("\n置换后的打分 == 对原打分做行列置换?", same)
print("=> 纯内容点积对顺序“置换等变”：模型分不清 token 到底排在第几位。")
print("   所以必须把“位置”额外注入 Q/K —— 这正是 RoPE 要做的事。")

Part B · 核心思想：用"旋转"编码位置
#

RoPE 的做法：把特征向量的维度两两配成一组，每一组看成一个二维平面上的点；然后按 token 所在的位置 $m$ 把这个二维点旋转一个角度 $m\cdot\omega$（$\omega$ 是这一组对应的频率）。

二维旋转就是最普通的旋转矩阵：

$$R(\phi)=\begin{bmatrix}\cos\phi & -\sin\phi\\ \sin\phi & \cos\phi\end{bmatrix}$$

下面用通用的 $R(\phi)$（这只是几何工具，不是 RoPE 前向）把同一个二维向量在位置 $m=0,1,2,\dots$ 上依次旋转，看它在圆上"走"出的轨迹。位置越大，转得越远。

def rot(phi):
    # 通用 2x2 旋转矩阵（纯几何工具，与作业实现无关）
    phi = torch.as_tensor(phi, dtype=torch.float32)
    c, s = torch.cos(phi), torch.sin(phi)
    return torch.stack([torch.stack([c, -s]), torch.stack([s, c])])

v = torch.tensor([1.0, 0.0])        # 某一维度对的初始二维向量
omega = 0.6                          # 这一组的频率（随便取一个值演示）
positions = torch.arange(0, 8)       # 位置 m = 0..7

pts = torch.stack([rot(m * omega) @ v for m in positions])

fig, ax = plt.subplots(figsize=(4.6, 4.6))
theta_c = torch.linspace(0, 2 * np.pi, 200)
ax.plot(torch.cos(theta_c), torch.sin(theta_c), color="0.8", lw=1)   # 单位圆
ax.quiver(torch.zeros(len(pts)), torch.zeros(len(pts)), pts[:, 0], pts[:, 1],
          angles="xy", scale_units="xy", scale=1, color=COL["blue"],
          width=0.008, alpha=0.85)
for m, p in zip(positions.tolist(), pts):
    ax.annotate(f"m={m}", (p[0] * 1.12, p[1] * 1.12), fontsize=8, ha="center")
ax.set_aspect("equal"); ax.axhline(0, lw=.5, c="k"); ax.axvline(0, lw=.5, c="k")
ax.set_xlim(-1.3, 1.3); ax.set_ylim(-1.3, 1.3)
ax.set_title("Same 2-D vector, rotated by position m")
plt.tight_layout(); plt.show()
print("位置每 +1，向量就多转一个固定角度 ω。位置被“编码”成了旋转角。")

Part C · 频率表：快频与慢频
#

如果所有维度对都用同一个 $\omega$，那不同维度携带的位置信息完全重复。RoPE 让每一组用不同的频率，按下式安排（$i$ 是维度对的索引，从 0 数起，$d$ 是特征维数）：

$$\omega_i=\theta^{-2i/d},\qquad \theta \approx 10000$$

i增大，2i/d增大，$\theta^{2i/d}$也增大，而它的倒数$\theta^{-2i/d}$越来越小，对应的就是频率小

  • $i$ 小 → 频率大 → 转得快（波长短），对相邻位置差敏感；
  • $i$ 大 → 频率小 → 转得慢（波长长），能覆盖很远的位置差。

这跟原始 Transformer 的正弦位置编码是同一种"多尺度"思路。下面把这条频率曲线画出来看形状（纯概念演示：这只是把上面的公式取值作图，帮助你理解"快 band vs 慢 band”）。

d_demo, theta = 64, 10000.0
i = torch.arange(0, d_demo // 2)              # 维度对索引 0..d/2-1
inv_freq = theta ** (-2.0 * i / d_demo)       # 频率表（把公式画出来）
wavelength = 2 * np.pi / inv_freq             # 波长 = 转一整圈需要的位置跨度

fig, ax = plt.subplots(1, 2, figsize=(9.5, 3.8))
ax[0].plot(i, inv_freq, marker="o", ms=3, color=COL["blue"])
ax[0].set_yscale("log"); ax[0].set_xlabel("dim-pair index  i")
ax[0].set_ylabel("frequency  $\\omega_i$ (log)")
ax[0].set_title("Frequency per dim-pair: fast $\\to$ slow")
ax[0].annotate("fast band", (1, inv_freq[1]), color=COL["orange"], fontsize=9)
ax[0].annotate("slow band", (d_demo // 2 - 8, inv_freq[-4]), color=COL["aqua"], fontsize=9)

# 三个代表性维度对：角度随位置怎么走（快的绕好几圈，慢的几乎不动）
m = torch.arange(0, 64)
for idx, name, c in [(0, "i=0 (fast)", COL["orange"]),
                     (8, "i=8 (mid)", COL["blue"]),
                     (28, "i=28 (slow)", COL["aqua"])]:
    ax[1].plot(m, torch.cos(m * inv_freq[idx]), color=c, lw=1.8, label=name)
ax[1].set_xlabel("position  m"); ax[1].set_ylabel("cos(m·$\\omega_i$)")
ax[1].set_title("Angle vs position for 3 dim-pairs"); ax[1].legend(fontsize=8)
plt.tight_layout(); plt.show()
print(f"i=0 波长≈{wavelength[0]:.1f}（转得快），i={d_demo//2-1} 波长≈{wavelength[-1]:.0f}（转得慢）")

Part D · 精髓：点积只依赖相对位置
#

这是 RoPE 最漂亮的性质。设某个维度对里，query 在位置 $m$、key 在位置 $n$，各自被旋转：

$$\langle R(m\omega)\,q,\; R(n\omega)\,k\rangle = q^{\top} R(m\omega)^{\top} R(n\omega)\, k = q^{\top} R\big((n-m)\omega\big)\, k$$

（用到 $R(a)^{\top}R(b)=R(b-a)$。）结果里绝对位置 $m,n$ 消失了，只剩下相对位置 $n-m$。也就是说：把两个 token 一起平移，注意力打分不变——模型学到的是"相隔多远"，而不是"各自在第几位"。

也就是给 Query 和 Key 都做 RoPE 旋转以后，它们的点积只和二者相距多少个位置有关，而不再分别依赖它们各自在第几个位置。

下面用通用 2D 旋转把这条恒等式测出来：固定偏移 $n-m$ 时打分是常数；改变偏移时打分才变化。

def rot(phi):
    phi = torch.as_tensor(phi, dtype=torch.float32)
    c, s = torch.cos(phi), torch.sin(phi)
    return torch.stack([torch.stack([c, -s]), torch.stack([s, c])])

torch.manual_seed(1)
q = torch.randn(2); k = torch.randn(2)      # 一个维度对里的 q,k（二维）
w = 0.5                                       # 这一组的频率

# (1) 固定相对偏移 offset=3，滑动绝对位置 m —— 打分应当是常数
offset = 3
ms = torch.arange(0, 20)
score_slide = [((rot(m * w) @ q) @ (rot((m + offset) * w) @ k)).item() for m in ms]

# (2) 改变相对偏移 —— 打分随之变化
offs = torch.arange(-10, 11)
score_by_off = [((rot(0 * w) @ q) @ (rot(o * w) @ k)).item() for o in offs]

fig, ax = plt.subplots(1, 2, figsize=(9.5, 3.6))
ax[0].plot(ms, score_slide, marker="o", ms=3, color=COL["blue"])
ax[0].set_xlabel("absolute position m (offset fixed = 3)")
ax[0].set_ylabel("q·k score"); ax[0].set_title("Slide both tokens: score is CONSTANT")
ax[0].set_ylim(min(score_slide) - 1, max(score_slide) + 1)
ax[1].plot(offs, score_by_off, marker="o", ms=3, color=COL["orange"])
ax[1].axvline(0, lw=.6, c="k")
ax[1].set_xlabel("relative offset (n - m)"); ax[1].set_ylabel("q·k score")
ax[1].set_title("Change the gap: score DOES vary")
plt.tight_layout(); plt.show()

flat = np.std(score_slide)
print(f"左图打分标准差 = {flat:.2e} （≈0，说明只依赖相对位置，与绝对位置无关）")
print("这正是 RoPE 想要的：注意力对“相隔多远”敏感，对“各自第几位”不敏感。")


左图打分标准差 = 1.95e-08 （≈0，说明只依赖相对位置，与绝对位置无关）
这正是 RoPE 想要的：注意力对“相隔多远”敏感，对“各自第几位”不敏感。

一个工程约定别忘了：RoPE 只施加在 Q 和 K 上，不作用于 V。原因正是 Part D——位置信息要进入的是"谁和谁匹配"的打分（$q\cdot k$），而 V 只是被加权求和的内容，不参与打分，所以不需要旋转。

🔬 拓展实验（自己动手，加深理解）
#

  1. 改 $\theta$ 看波长：把 Part C 里的 theta 从 10000 改成 100 或 1e6，重画频率曲线，观察最慢那一组的波长怎么变。思考：上下文越长，你希望 $\theta$ 更大还是更小？
  2. 验证 $R(a)^\top R(b)=R(b-a)$：用你的 rot，随便取两个角度，数值上核对这个矩阵恒等式——它就是 Part D 结论的代数来源。
  3. 相邻配对 vs 前后半配对：RoPE 有两种常见的"配对法"——把维度 (0,1),(2,3),... 相邻两两配对，或把前半 [0:d/2] 和后半 [d/2:d] 对应配对。用一个小张量画出两种配对下"哪一维和哪一维成对"，想清楚你的实现选哪一种，以及 cos/sin 要怎么对齐。（这会直接影响你能否通过 test_rope。）
  4. 旋转是保长的：随机取一个二维向量，旋转任意角度后打印它的模长——确认旋转不改变长度（正交变换）。这解释了为什么 RoPE 不会破坏向量的尺度。

✏️ 作业连接：run_rope 引导骨架
#

对应 tests/adapters.py::run_rope，测试是 tests/test_model.py::test_rope（conftest.py 里 theta=10000、token_positions=arange、atol=1e-5）。

下面是给你填的骨架（... 处留白，不要直接跑通）。把上面的直觉翻译成对任意前导维 ... 都通用的张量运算。几个想清楚再动手的点：

  • 频率表 $\omega_i=\theta^{-2i/d}$ 只依赖 d_k，可以在 __init__ 里预计算并缓存到 max_seq_len（用 register_buffer，别当成可学习参数）。
  • 角度 = 位置与频率的外积：token_positions（形状 ... seq）对上 inv_freq（形状 d_k/2）。位置来自参数 token_positions，不要假设它就是 0..seq-1。
  • 把输入按相邻维配对还是前后半配对？两种都能对，但 cos/sin 的排布必须和你的配对方式一致——拿 d_k=4、seq=2 的玩具张量核对。
  • 对每一对施加二维旋转（$x'=x\cos-y\sin,\; y'=x\sin+y\cos$），再重组回原形状。
  • 只在 Q/K 上调用；forward 返回和输入同形状的张量。
import einops

class RotaryPositionalEmbedding(nn.Module):
    def __init__(self, theta: float, d_k: int, max_seq_len: int):
        super().__init__()
        # step 1: 建维度对索引 i = 0,1,...,d_k/2 - 1，算频率表 inv_freq = theta^(-2i/d_k)
        i = torch.arange(d_k // 2, dtype=torch.float32) # (d_k/2, )
        inv_freq = theta ** (-2 * i / d_k) # (d_k/2, )

        # step 2: 位置 0..max_seq_len-1 与 inv_freq 做外积，得到角度表 (max_seq_len, d_k/2)
        # 需要构造一个pos 向量来储存位置，然后进行外积。这样得到的angles表就是我们的旋转角度对应表，对于每个pos的每一对两两组合的维度，我们有一个旋转角度
        # 这样就实现了加入位置信息
        pos = torch.arange(max_seq_len) # (max_seq_len, )
        angles = torch.outer(pos, inv_freq) # 两个一维向量，做外积操作，(max_seq_len, d_k/2)

        # step 3: 由 angles 预计算 cos / sin，并用 register_buffer 缓存（非可学习参数）
        # 用register的意义是：会把数据缓存到显卡上，减少了后续的数据搬运
        self.register_buffer("cos_cached", torch.cos(angles), persistent=False) # (max_seq_len, d_k/2)
        self.register_buffer("sin_cached", torch.sin(angles), persistent=False) # (max_seq_len, d_k/2)
    

    def forward(self, x, token_positions):
        # x: (..., seq, d_k)   token_positions: (..., seq)
        # step 4: 用 token_positions 从缓存里取出对应的 cos / sin（注意任意前导维要能广播）
        # 使用整型张量索引，用token_positions中的每一个元素（数字）去做索引
        cos = self.cos_cached[token_positions] # (seq, d_k/2)
        sin = self.sin_cached[token_positions]

        # step 5: 把 x 的最后一维按你选定的方式配对，拆成两半 (x1, x2)
        # 先转变形状，然后沿着最后一维拆分
        # torch.unbind(x_pair, dim=-1)：沿最后一维拆成两个分量
        x1, x2 = torch.unbind(einops.rearrange(x, "... seq (pairs two) -> ... seq pairs two", two=2), dim=-1) # (..., seq, d_k // 2)

        # step 6: 对每一对施加二维旋转： x1' = x1*cos - x2*sin ; x2' = x1*sin + x2*cos
        x_1, x_2 = x1 * cos - x2 * sin, x1 * sin + x2 * cos

        # step 7: 把旋转后的两半重组回 (..., seq, d_k)，保证输出与输入同形状
        return einops.rearrange(torch.stack([x_1, x_2], dim=-1), "... seq pairs two -> ... seq (pairs two)", two=2)  # (..., seq, d_k)

print("  uv run pytest tests/test_model.py::test_rope -x")

小结
#

  • 为什么要位置编码：自注意力的纯内容点积对顺序置换等变——不额外注入位置，模型就是个词袋。
  • RoPE 的思想：特征维两两配对，按 位置 × 频率 做二维旋转，把位置写进 Q/K。
  • 频率表 $\omega_i=\theta^{-2i/d}$：多尺度，有快 band（对近距离敏感）和慢 band（覆盖远距离）。
  • 精髓：旋转后 $q\cdot k$ 只依赖相对位置 $(m-n)$，绝对位置消失（源自 $R(a)^\top R(b)=R(b-a)$）。
  • 工程约定：只对 Q/K 施加，不动 V；位置来自 token_positions，别假设是 0..seq-1；频率表可缓存到 max_seq_len。
