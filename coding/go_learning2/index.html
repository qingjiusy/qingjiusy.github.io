type
#

go语言中的type可以用来定义别名类型，给已有类型起一个新名字。比如type myint int，意思就是声明一种行的数据类型myint， 是int的一个别名。

同时也经常用来定义一个结构体：

type Book struct {
	title string
	auth  string
}

注意，如果构建一个其他函数，然后传入一个结构体作为参数，那么函数执行后，原来的结构体内数据**不会受到影响！**因为函数会自己创造出一个结构体的副本，而非直接修改原来的结构体。

为了修改原来的结构体，需要使用结构体指针作为传入的参数：

func changeBook(book Book) {
	//传递一个book的副本
	book.auth = "666"
}

func changeBook2(book *Book) {
	//指针传递
	book.auth = "777"
}

面向对象
#

面向对象类的表示与封装
#

有关于对象中方法的实现，我们可以这样去做：

type Hero struct {
	//如果说类的属性首字母大写, 表示该属性是对外能够访问的，否则的话只能够类的内部访问
	Name  string
	Ad    int
	level int
}

func (this Hero) Show() {
	fmt.Println("Name = ", this.Name)
	fmt.Println("Ad = ", this.Ad)
	fmt.Println("Level = ", this.Level)
}

func (this Hero) GetName() string {
	return this.Name
}

func (this Hero) SetName(newName string) {
	//this 是调用该方法的对象的一个副本（拷贝）
	this.Name = newName
}

但是仍然要注意，这种方式虽然没错，但是SetName方法还是没有实现我们要去做的目的。

因此我们在创建类的方法的时候通常都应该使用指针来创建，这样可以保证之后this可以正确的实现我们的目的：

func (this *Hero) Show() {
	fmt.Println("Name = ", this.Name)
	fmt.Println("Ad = ", this.Ad)
	fmt.Println("Level = ", this.level)
}

func (this *Hero) GetName() string {
	return this.Name
}

func (this *Hero) SetName(newName string) {
	//this 是调用该方法的对象的一个副本（拷贝）
	this.Name = newName
}

注意：如果说类的属性首字母大写, 表示该属性是对外能够访问的，否则的话只能够类的内部访问

面向对象继承
#

在这里举一个例子，一个超人类SuperMan继承人类Human：

type Human struct {
	name string
	sex  string
}

func (this *Human) Eat() {
	fmt.Println("Human.Eat()...")
}

func (this *Human) Walk() {
	fmt.Println("Human.Walk()...")
}

//=================

type SuperMan struct {
	Human //SuperMan类继承了Human类的方法

	level int
}

当然可以重定义父类的方法，也可以创建子类新方法：

//重定义父类的方法Eat()
func (this *SuperMan) Eat() {
	fmt.Println("SuperMan.Eat()...")
}

//子类的新方法
func (this *SuperMan) Fly() {
	fmt.Println("SuperMan.Fly()...")
}

这个子类定义的两种方法：

//方法一
s := SuperMan{Human{"li4", "female"}, 88}
//方法二
var s SuperMan
s.name = "li4"
s.sex = "male"
s.level = 88

面向对象多态
#

接口体现多态的关键点：

  1. 定义统一的接口（Interface）。
  2. 多个类实现该接口，各自定义不同的行为。
  3. 通过接口类型调用，不关心具体实现类是谁。
  4. 在运行时，根据实际对象类型决定调用哪个方法 —— 这就是多态。

定义一个接口：

//本质是一个指针
type AnimalIF interface {
	Sleep()
	GetColor() string //获取动物的颜色
	GetType() string  //获取动物的种类
}

这意思是：任何实现了Sleep、GetColor、GetType这三个方法的类型，都是AnimalIF类型，不需要显式地“继承”这个interface。

具体实现接口的两个类：

//具体的类
type Cat struct {
	color string //猫的颜色
}

func (this *Cat) Sleep() {
	fmt.Println("Cat is Sleep")
}

func (this *Cat) GetColor() string {
	return this.color
}

func (this *Cat) GetType() string {
	return "Cat"
}

//具体的类
type Dog struct {
	color string
}

func (this *Dog) Sleep() {
	fmt.Println("Dog is Sleep")
}

func (this *Dog) GetColor() string {
	return this.color
}

func (this *Dog) GetType() string {
	return "Dog"
}

接口多态的体现：

var animal AnimalIF //接口的数据类型， 父类指针
animal = &Cat{"Green"}
animal.Sleep() //调用的就是Cat的Sleep()方法 , 多态的现象
animal = &Dog{"Yellow"}
animal.Sleep() // 调用Dog的Sleep方法，多态的现象

多态基本的要素：

  1. 有一个父类（接口）
  2. 有子类（实现了父类的全部接口方法）
  3. 父类类型的变量（指针）指向（引用）子类的具体数据变量

通用万能类型
#

go语言中的通用万能类型是interface{}。

其中go语言中的空接口，int，string，float32等等都实现了interface{}。可以用interface{}类型引用任意的数据类型。

类型断言
#

我们可以给interface{}提供 “类型断言” 的机制，比如：

func myFunc(arg interface{}) {
	//类型断言
	value, ok := arg.(string)
	if !ok {
		fmt.Println("arg is not string type")
	} else {
		fmt.Println("arg is string type, value = ", value)

		fmt.Printf("value type is %T\n", value)
	}
}

在这里，我们用的arg.(string)就是一个类型断言。判断arg参数是不是一个string。

变量的内置pair结构
#

golang中任何一个变量应该时包含type和value的，其中type可以具体分为两种类型：一种是static type，一种是concrete type。

在这里，a的pair是pair<statictype:string, value:"aceld">，allType的pair也是如此（因为被a赋值，传递了）。

func main() {

	var a string
	//pair<statictype:string, value:"aceld">
	a = "aceld"

	//pair<type:string, value:"aceld">
	var allType interface{}
	allType = a

	str, _ := allType.(string)
	fmt.Println(str)
}

再看这段代码，注意这里为什么r.(Writer)这个断言会成功？因为w和r其实具体的type是一致的。

type Reader interface {
	ReadBook()
}
type Writer interface {
	WriteBook()
}

//具体类型
type Book struct {
}
func (this *Book) ReadBook() {
	fmt.Println("Read a Book")
}
func (this *Book) WriteBook() {
	fmt.Println("Write a Book")
}

func main() {
	//b: pair<type:Book, value:book{}地址>
	b := &Book{}

	//r: pair<type:, value:>
	var r Reader
	//r: pair<type:Book, value:book{}地址>
	r = b
	r.ReadBook()

	var w Writer
	//r: pair<type:Book, value:book{}地址>
	w = r.(Writer) //此处的断言为什么会成功？ 因为w r 具体的type是一致
	w.WriteBook()
}

reflect反射机制
#

直观的来说就是把变量里面的东西给“照出来”。

reflect机制中有两个重要的接口：Valueof和Typeof。如果Valueof接收的值为空（非法），那么返回为0。如果Typeof接收的值为非法，那么返回null。

import (
	"fmt"
	"reflect"
)

func reflectNum(arg interface{}) {
	fmt.Println("type : ", reflect.TypeOf(arg))
	fmt.Println("value : ", reflect.ValueOf(arg))
}

func main() {
	var num float64 = 1.2345

	reflectNum(num)
}

结构体标签
#

反射解析结构体标签Tag
#

在下面这段代码中，是定义结构体（struct）时使用 tag（标签）的示例。

type resume struct {
	Name string `info:"name" doc:"我的名字"`
	Sex  string `info:"sex"`
}

这是定义了一个名为resume的结构体，包含两个字段。

每个字段后面的info:"..." doc:"..."是结构体标签（Tag），它是Go的语法特性，用来给字段添加元信息（Metadata），可在运行时通过反射（reflect包）读取。

比如在这里，我们就可以用.Tag去具体Get到对应的内容：

func findTag(str interface{}) {
	t := reflect.TypeOf(str).Elem()

	for i := 0; i < t.NumField(); i++ {
		taginfo := t.Field(i).Tag.Get("info")
		tagdoc := t.Field(i).Tag.Get("doc")
		fmt.Println("info: ", taginfo, " doc: ", tagdoc)
	}
}

func main() {
	var re resume
	findTag(&re)
}

结构体标签在json中的应用
#

那么想当然，我们想知道tag具体的应用。实际上在json上就常被应用！

其中先知道有这个标准库encoding/json，可以把结构体转变为json文件。

package main

import (
	"encoding/json"
	"fmt"
)

type Movie struct {
	Title  string   `json:"title"`
	Year   int      `json:"year"`
	Price  int      `json:"rmb"`
	Actors []string `json:"actors"`
}

func main() {
	movie := Movie{"喜剧之王", 2000, 10, []string{"xingye", "zhangbozhi"}}

	//编码的过程  结构体---> json
	jsonStr, err := json.Marshal(movie)
	if err != nil {
		fmt.Println("json marshal error", err)
		return
	}

	fmt.Printf("jsonStr = %s\n", jsonStr)
}

在这段代码中，我们通过tag对json中的字段名进行了规定。这样的结果是，在后续代码中我们使用了json转换的方法json.Marshal，可以看到原来的结构体对应生成的json是：jsonStr = {"title":"喜剧之王","year":2000,"rmb":10,"actors":["xingye","zhangbozhi"]}。

当然这里代码也可以实现把json字符串变成了结构体：

//解码的过程 jsonstr ---> 结构体
//jsonStr = {"title":"喜剧之王","year":2000,"rmb":10,"actors":["xingye","zhangbozhi"]}
myMovie := Movie{}
err = json.Unmarshal(jsonStr, &myMovie)
if err != nil {
	fmt.Println("json unmarshal error ", err)
	return
}

fmt.Printf("%v\n", myMovie)

goroutine
#

由来
#

早期的单进程操作系统，就是在顺序执行进程：

单进程时代的两个问题？

  1. 单一执行流程、计算机智能一个任务一个任务处理
  2. 进程阻塞所带来的的CPU浪费时间

所以能不能宏观的执行多个任务呢？

于是就有了多线程/多进程的操作系统！

所以多线程/多进程解决了阻塞问题！但是又面临新问题：cpu的浪费时间成本。

进程/线程的数量越多，切换成本就越大，也就越浪费。

多线程随着同步竞争（如锁、竞争资源冲突等），开发设计变得越来越复杂。

接下来解释一下协程（Coroutine）与线程（Thread）在计算机系统中所处的位置：

用户空间 vs 内核空间：

  1. 用户空间（User Space）：运行用户程序的区域，比如你写的 Python、Go、Java 代码就跑在用户空间。
  2. 内核空间（Kernel Space）：由操作系统控制的区域，负责资源调度、进程管理等。线程是由操作系统调度的，因此在线程层面需要内核支持。

CPU视野：

  1. CPU只能看到线程，不能直接看到协程，因为协程调度在用户空间完成，不进入内核。
  2. 从CPU的角度，执行的还是线程（即蓝色区域）。

我们通过协程调度器，可以让一个线程对应多个协程。这样就省去了线程调度所要消耗的时间，这我们称为N比1的协程对应关系。

那么为什么协程调度器的存在就可以节省开支？协程本身不还是要切换？

关键问题：协程调度器到底省了什么开支？

回顾一下线程上下文切换的成本：

当线程之间切换时，操作系统需要执行以下操作：

  • 保存/恢复 CPU 寄存器
  • 切换内存页表（上下文）
  • 切换线程栈
  • 涉及用户态 ↔ 内核态切换（系统调用）

这些操作是重量级的开销，特别频繁时会严重影响性能。

而协程的切换是纯用户空间的操作

协程之间共享同一个线程，不需要进入内核

协程调度器只需要：

  • 保存/恢复程序计数器（PC）
  • 切换栈指针（或者 coroutine 的状态对象）
  • 调整协程状态（就绪、运行、挂起等）

这就是轻量级调度，所以开销极低。

M:N模型
#

目前在N比1的模式下，如果一个协程阻塞了，因为是轮询，所以会影响我下一个协程的调度。如果仍然是1比1，和之前直接切换线程没有区别，仍然不是好方法。

因此我们考虑使用M比N模型：

显然可以看出这里的核心是优化这个协程调度器，调度器越好，cpu的利用率越高。

golang对协程的处理
#

将协程（co-routine）改成Goroutine。内存仅几KB，并且可以灵活调度。

老调度器有几个缺点：

  1. 创建、销毁、调度G都需要每个M获取锁，这就形成了激烈的锁竞争。
  2. M转移G会造成延迟和额外的系统负载。
  3. 系统调用（CPU在M之间的切换）导致频繁的线程阻塞和取消阻塞操作增加了系统开销。

接下来了解一下GMP：

在这里，显然，我们的最多并行数量就是我们GOMAXPROC中设定的数量，具体执行某一个G时我们需要把它拿到P中。

多个P会并发调度goroutine，且只要CPU核心数允许，就是真正的“并行”执行，而不是仅仅依靠线程切换实现的“并发”。

调度过程

  1. 协程创建与入队
  • 每当你调用go someFunc()，就会创建一个新的G（goroutine）。
  • G会被放入某个P的本地队列，或者全局队列中等待执行。
  1. P和M的绑定
  • 一个P（Processor）绑定一个M（线程），共同工作。
  • 一个时刻最多有GOMAXPROCS个活跃的P。
  • 没有空闲的P，新的M就不能运行任何G。
  1. 执行goroutine
  • M从P的本地队列中取出G并执行。
  • 本地队列为空时，P可以从全局队列或别的P那里“偷”G。
  1. 线程复用与休眠
  • 如果M执行的G阻塞了（如 I/O），则会释放P，M 可以被挂起或回收。
  • P会寻找空闲M来继续执行其他G。

创建goroutine
#

只需要用go关键字就能来创建一个go协程。

来看一个简单的并发情况：

package main

import (
	"fmt"
	"time"
)

//子goroutine
func newTask() {
	i := 0
	for {
		i++
		fmt.Printf("new Goroutine : i = %d\n", i)
		time.Sleep(1 * time.Second)
	}
}

//主goroutine
func main() {
	//创建一个go程 去执行newTask() 流程
	go newTask()

	//fmt.Println("main goroutine exit")

	i := 0
	for {
		i++
		fmt.Printf("main goroutine: i = %d\n", i)
		time.Sleep(1 * time.Second)
	}
}

在这里，我们有一个main goroutine和一个new goroutine。在这里两个goroutine是并发的。

注意这里，如果我们不在主goroutine（即main()函数）中执行那个循环，而是直接退出。那么子goroutine也会直接结束。

这是因为主goroutine（即 main() 函数）执行完毕并退出时，整个程序就会结束，无论是否还有其他goroutine（比如子goroutine）正在运行。

go函数中退出go协程
#

在一个go协程中，有时候return不能满足我们的需求，我们需要一个特定的退出协程的函数。

在这里我们常常使用runtime.Goexit()。

但是如果我们的主go程需要某个go协程的返回值，直接通过返回值来拿是拿不到的，比如下面的代码就是不行的：

return := go func(a int, b int) bool {
	fmt.Println("a = ", a, ", b = ", b)
	return true
}(10, 20)

因为go协程在执行完以后不会把它抛给上一层。

channel
#

channel的基本定义与使用
#

也就是管道。两个goroutine之间通过channel进行通信。

定义一个channel：c := make(chan int)

比如在下面的代码中，两个协程就是通过channel c来相互通信：

package main

import "fmt"

func main() {
	//定义一个channel
	c := make(chan int)

	go func() {
		defer fmt.Println("goroutine结束")

		fmt.Println("goroutine 正在运行...")

		c <- 666 //将666 发送给c
	}()

	num := <-c //从c中接受数据，并赋值给num

	fmt.Println("num = ", num)
	fmt.Println("main goroutine 结束...")
}

在管道通信中，常常会有接受方已经执行到接受的步骤，在这里就是num := <-c，而发送方还没有，也就是c <- 666。

这时候接受方会用阻塞来让自己等待接受channel中的结果。这样就在无形之中达到了一个同步的结果。

channel有无缓存同步问题
#

无缓存channel
#

下面是一个无缓存的channel的示意图：

在第1步，两个goroutine都到达通道，但哪个都没有开始执行发送或者接收。

在第2步，左侧的goroutine将它的手伸进了通道，这模拟了向通道发送数据的行为。这时，这个goroutine会在通道中被锁住，直到交换完成。

在第3步，右侧的goroutine将它的手放入通道，这模拟了从通道里接收数据。这个goroutine一样也会在通道中被锁住，直到交换完成。

在第4步和第5步，进行交换，并最终，在第6步，两个goroutine都将它们的手从通道里拿出来，这模拟了被锁住的goroutine得到释放。两个goroutine现在都可以去做其他事情了。

有缓存channel
#

与之对应的就是有缓存的channel。

在第1步，右侧的goroutine正在从通道接收一个值。

在第2步，右侧的这个goroutine独立完成了接收值的动作，而左侧的goroutine正在发送一个新值到通道里。

在第3步，左侧的goroutine还在向通道发送新值，而右侧的 goroutine 正在从通道接收另外一个值。这个步骤里的两个操作既不是同步的，也不会互相阻塞。

最后，在第4步，所有的发送和接收都完成，而通道里还有几个值，也有一些空间可以存更多的值。

接下来我们看一段使用有缓存channel的代码：

package main

import (
	"fmt"
	"time"
)

func main() {
	c := make(chan int, 3) //带有缓冲的channel

	fmt.Println("len(c) = ", len(c), ", cap(c)", cap(c))

	go func() {
		defer fmt.Println("子go程结束")

		for i := 0; i < 4; i++ {
			c <- i
			fmt.Println("子go程正在运行, 发送的元素=", i, " len(c)=", len(c), ", cap(c)=", cap(c))
		}
	}()

	time.Sleep(2 * time.Second)

	for i := 0; i < 4; i++ {
		num := <-c //从c中接收数据，并赋值给num
		fmt.Println("num = ", num)
	}

	fmt.Println("main 结束")
}

在这里我们子go程发第四个元素的时候就会被阻塞，但是一旦缓存有空余后，仍然可以正常的去发送。但是我们不能保证这几个print最后哪个先被执行。

channel的关闭
#

  1. channel不像文件一样需要经常去关闭，只有当你确实没有任何发送数据了，或者你想显式的结束range循环之类收才关闭。
  2. 关闭channel后，无法向channel，再发送数据（引发panic错误后导致接收立即返回零值）；
  3. 关闭channel后，可以继续从channel接收数据；
  4. 对于nil channel，无论收发都会被阻塞

channel与range
#

典型的就是下面这段代码：

for data := range c {
    fmt.Println(data)
}

这段代码是用Go(Golang)编写的一个for循环，用于从channel(c)中接收数据并打印。具体解释如下：

  1. for … range语法

这是 Go 语言中特有的一种用于遍历集合类型（如array、slice、map、channel）的简洁语法。

对于channel，range会不断从channel中接收数据，直到channel被关闭。

  1. data := range c

每次从channel c中接收到的数据会被赋值给 data，然后执行循环体中的代码。

  1. fmt.Println(data)

将每次接收到的数据打印到控制台。

关键特性：

  1. 阻塞特性

如果channel c中没有数据可读，循环会阻塞等待，直到有新的数据写入c或c被关闭。

  1. 自动退出

当channel c被关闭且数据完全读取后，循环会自动结束，无需显式break。

channel与select
#

单流程下一个go只能监控一个channel的状态，select可以完成监控多个channel的状态。

写一个小案例，有关于斐波那契数列

package main

import "fmt"

func fibonacii(c, quit chan int) {
	x, y := 1, 1

	for {
		select {
		case c <- x:
			//如果c可写，则该case就会进来
			x = y
			y = x + y
		case <-quit:
			fmt.Println("quit")
			return
		}
	}
}

func main() {
	c := make(chan int)
	quit := make(chan int)

	//sub go
	go func() {
		for i := 0; i < 10; i++ {
			fmt.Println(<-c) //这个goroutine会一直等待，直到c有数据传入。 
		}

		quit <- 0
	}()

	//main go
	fibonacii(c, quit)
}

所以说select可以同时监控多路channel的状态。

GO Modules
#

GO MOdules是Go语言的依赖解决方案。

Go moudles目前集成在Go的工具链中，只要安装了Go，自然而然也就可以使用Go moudles了，而Go modules的出现也解决了在Go1.11前的几个常见争议问题：

  1. Go语言长久以来的依赖管理问题。
  2. “淘汰”现有的GOPATH的使用模式。
  3. 统一社区中的其它的依赖管理工具（提供迁移功能）。

#

  1. 没有版本控制概念

不知道自己当前什么版本，也不能拉取自己希望的版本。

  1. 无法同步一致第三方版本号
  2. 无法指定当前项目引用的第三方版本号
