react中的路由实现
#

下载react路由相关的库
# 

npm i react-router-dom

便可在package.json中看到相关的库已经被安装。

具体实现流程
# 

import {createBrowserRouter, RouterProvider} from 'react-router-dom'

const router = createBrowserRouter([
  {
    path:'/login',
    element:<div>login page</div>
  },
  {
    path:'/article',
    element:<div>article page</div>
  }
])

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    <RouterProvider router={router}></RouterProvider>
  </React.StrictMode>
);

在跑起来的端口上，不同的路由上确实可以看到不同的页面，证明路由已经正确生效。

但是这毕竟只是最简单的实现，实际项目中不可能这么简单。

路由导航
#

路由系统中的多个路由之间需要进行路由跳转，并且在跳转的同时有可能需要传递参数进行通信。实现方法有声明式导航和编程式导航

声明式导航
#

声明式导航是指通过在模版中通过<Link/>组件描述出要跳转到哪里去，比如后台管理系统的左侧菜单通常使用这种方式进行。

<Link to="/article">文章</Link>

语法说明：通过给组件的to属性指定要跳转到路由path，组件会被渲染为浏览器支持的a链接，如果需要传参直接通过字符串拼接的方式拼接参数即可。

编程式导航
#

编程式导航是指通过useNavigate钩子得到导航方法，然后通过调用方法以命令式的形式进行路由跳转，比如想在登录请求完毕之后跳转就可以选择这种方式，更加灵活。

import { Link,useNavigate } from "react-router-dom"
const Login = () => {
    const navigate = useNavigate()
    return (
    <div>
        <button onClick={() => navigate('/article')}>jump !!!</button>
    </div>
    )
}

导航传参
#

同时传参也有两种写法，传参涉及到两个步骤，一个是参数传递，一个是参数接受。

第一种写法是searchParams传参。简单一点就是在路径后面通过一个问号拼接参数：

//传参
navigate('/article?id=1001&name=jack')

//接收参数
const [params] = useSearchParams()
let id = params.get('id')

第二种传参方式是params传参。注意需要在路由中加上对应的占位符！

//传参
navigate('/article/1001')

//接收参数
const params = useParams()
let id = params.id

在一级路由中又内嵌了其他路由，这种关系就叫做嵌套路由，嵌套至一级路由内的路由又称作二级路由，例如在下图的一级路由layout中，如果切换点击“看板”或者“关于”，右边就对应显示相关的二级路由渲染。

实现步骤：

默认二级路由
#

当访问的是一级路由时，默认的二级路由组件可以得到渲染，只需要在二级路由的位置去掉path，设置index属性为true。

注意，同时Link组件中的to的属性也要改动，因为现在没有path了，<Link to="/">即可。

404路由
#

场景：当浏览器输入url的路径在整个路由配置中都找不到对应的path，为了用户体验，可以使用404兜底组件进行渲染。

实现步骤：

  1. 准备一个NotFound组件
  2. 在路由表数组的末尾，以*号作为路由path配置路由

配置别名路径
#

CRACO配置Webpack别名路径，主要是为了优化react项目的 import路径，让src目录下的文件更容易引用，避免复杂的相对路径，提高代码可读性和可维护性。

下载CRACO。

npm i -D @craco/craco

然后在项目目录下新建craco.config.js，写入：

const path = require('path')

module.exports = {
    webpack:{
        alias:{
            '@': path.resolve(__dirname,'src')
        }
    }
}

之后在package.json中替换一下script命令，如下：

"scripts": {
    "start": "craco start",
    "build": "craco build",
    "test": "react-scripts test",
    "eject": "react-scripts eject"
  },

这样就完成了，可以在项目的import中使用@来表示src了！

同时为了效率，可以启用vscode中的代码联想，方便我们开发，只需要在主目录下新建文件jsconfig.json：

{
    "compilerOptions": {
        "baseUrl": "./",
        "paths":{
            "@/*":[
                "src/*"
            ]
        }
    }
}

实现数据Mock
#

数据Mock是指在前后端分类的开发模式下，前端可以在没有实际后端接口的支持下先进行接口数据的模拟，进行正常的业务功能开发。

本次只用json-server来实现数据Mock。json-server是一个node包，可以在不到30秒内获得零编码的完整的Mock服务。

然后去package.json中加一条script命令，如下：

"server": "json-server ./server/data.json --port 8888"

管理账目列表
#

老样子，使用redux做一个state，写写要注意的内容。 比如编写异步逻辑的方法：

//解构actionCreate函数
const {setBillList} = billStore.actions
//编写异步
const getBillList = () => {
    //编写异步逻辑
    return async (dispatch) => {
        const res = await axios.get('http://localhost:8888/ka')
        //触发同步reducer
        dispatch(setBillList(res.data))
    }
}

还有一点就是虽然modules中编写了reducer然后默认导出了，也就是export default reducer，在导入的时候是可以给你换名字的！！也就是可以在index.js中这样导入：

import billReducer from './modules/billStore'

const store = configureStore({
    reducer: {
        bill: billReducer
    }
})

完成了这些以后，就是去对应的界面中使用了，账目列表主要是在Layout中使用，因此在一开始的渲染部分要使用这个state，注意这个里面要使用useEffect这个钩子函数来实现初始渲染：

//在Layout的index.js中
const dispatch = useDispatch()
  useEffect(() => {
    dispatch(getBillList())
  },[dispatch]
)

控制时间显示
#

一样的思路，构造一个状态，按时间选择框通过事件触发状态设置函数来更改状态。

注意点：一开始这里有一个疑惑，为什么这里初始值设置要使用函数返回值的形式？不能直接传入new Date()吗？

//控制时间显示
  const [currentDate, setCurrentDate] = useState(()=>{
    return new Date()
  })

原因是如果你直接传入new Date()，它会在每次组件渲染时执行new Date()，然后将返回的时间对象作为useState的初始值。这意味着即使useState只在初始渲染时使用该值，new Date()也会在每次渲染时执行一次，尽管其返回值不会被使用（仅在初始渲染时有效）。

而使用函数返回值时，react只会在初次渲染时调用该函数，并使用返回值作为初始状态。这样避免不必要的计算，函数只有在第一次渲染时执行，后续渲染不会重复调用new Date()。

同时要注意用dayjs去保证格式正确。

计算选择月份的统计数据
#

通过useMemo实现业务逻辑：

const monthResult = useMemo(()=>{
    //支出/收入/结余
    const pay = currentMonthList.filter(item=>item.type==='pay').reduce((a, c)=>a + c.money, 0)
    const income = currentMonthList.filter(item=>item.type==='income').reduce((a, c)=>a + c.money, 0)
    return {
      pay,
      income,
      total: pay + income
    }
  }, [currentMonthList])
