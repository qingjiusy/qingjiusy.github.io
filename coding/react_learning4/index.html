登录-封装request请求模块
#

整个项目会用到很多网络请求，所以使用axios来做好封装是比较利于统一管理的。

axios的封装处理：

  1. 根域名配置
  2. 超市时间
  3. 请求拦截器 / 相应拦截器

请求拦截器：

http.interceptors.request.use((config)=> {
    return config
  }, (error)=> {
    return Promise.reject(error)
})

在请求拦截器中，在每次发送 HTTP 请求前先做拦截，然后可以插入一些自定义的配置，比如对于参数的处理。比如在这里接受两个回调，一个是成功一个是失败。

响应拦截器

http.interceptors.response.use((response)=> {
    // 2xx 范围内的状态码都会触发该函数。
    // 对响应数据做点什么
    return response.data
  }, (error)=> {
    // 超出 2xx 范围的状态码都会触发该函数。
    // 对响应错误做点什么
    return Promise.reject(error)
})

这是在响应返回到客户端之前做拦截，然后处理。

之后会在这两个拦截器中间重点处理返回的数据，做业务开发。

登录-实现token的持久化
#

现存问题：redux存入了token之后用如果刷新浏览器，token会丢失（持久化就是防止刷新时丢失token）。

通过观察f12中redux的state，可以看到一刷新就丢失了。

问题原因是redux是基于浏览器内存的储存方式，刷新时状态恢复为初始值。也就是这里：

initialState:{
        token:''
    },

实现方案是配合localStorage去实现:

要注意，在现实开发中，这种方法其实占到了95%以上！！

一般来说，在实际的开发中的用户登录流程：

首次的时候：用户前端输入，然后后端验证返回token，前端去存到localstorage 接下来，前端直接拿到本地的token发给后端验证

封装token的存取删方法
#

为什么要封装呢？

因为对于token的各类操作在项目中多个模块中都有用到，为了共享复用我们可以直接把它封装成工具函数。

之后就可以在其他地方复用这些工具函数了，如下：

//封装和token有关的方法 存 取 删
const TOKENKEY = 'token_key'
function setToken(token) {
    localStorage.setItem(TOKENKEY, token)
}

function getToken() {
    return localStorage.getItem(TOKENKEY)
}

function removeToken() {
    localStorage.removeItem(TOKENKEY)
}

export {
    setToken,
    getToken,
    removeToken
}

axios请求头注入token
#

Token作为用户的一个标识数据，后端很多接口都会以它作为接口权限判断的依据；请求拦截器注入Token之后，所有用到Axios实例的接口请求都自动携带了Token。

方法：

  • Axios请求拦截器请求头中注入Token
  • 调用接口测试Token是否成功携带

实现后的请求拦截器, 注意这里要配合后端写的代码：

// 添加请求拦截器
request.interceptors.request.use((config)=> {
  //操作config 注入token数据
  const token = getToken()
  if(token){
    config.headers.Authorization = `Bearer ${token}`
  } 
    return config
  }, (error)=> {
    return Promise.reject(error)
})

config.headers.Authorization这个写法是由axios决定的，而Bearer ${token}这个拼接写法是由后端来决定好的。

使用token做路由权限的控制
#

有些路由页面内的内容信息比较敏感，如果用户没有经过登录获取到有效Token，是没有权限跳转的，根据Token的有无控制当前路由是否可以跳转就是路由的权限控制。

import { getToken } from "@/utils"
import { Navigate } from "react-router-dom"

function AuthRoute({children}) {
    const token = getToken()
    if(token) {
        return <>{children}</>
    } else {
        //用一个重定向组件
        return <Navigate to={'/login'} replace/>
    }
}

很显然，在这里有token就和之前的写法一样，没有token就直接重定向到登录界面。

退出登录实现
#

退出是一个很常见的通用业务逻辑，一般来说退出登录要做什么？

必要通用的退出业务逻辑：

  1. 提示用户是否确认要退出（危险操作，二次确认）
  2. 用户确认之后清除用户信息（Token以及其它个人信息）
  3. 跳转到登录页（为下次登录做准备）

redux中要新增一个清除信息的action:

clearUserInfo(state){
            state.token = ''
            state.userInfo = {}
            removeToken()
        }

在退出的按钮上实现的操作：

const onConfirm = () => { 
    dispatch(clearUserInfo())
    navigate('/login')
}

处理token失效
#

什么是Token失效？

为了用户的安全和隐私考虑，在用户长时间未在网站中做任何操作且规定的失效时间到达之后，当前的Token就会失效，一旦失效，不能再作为用户令牌标识请求隐私数据。

前端如何知道Token已经失效了？

通常在Token失效之后再去请求接口，后端会返回401状态码，前端可以监控这个状态做后续的操作

Token失效了前端做什么？

  1. 在axios拦截中监控401状态码
  2. 清除失效Token，跳转登录

实现这些操作的响应拦截器：

request.interceptors.response.use((response)=> {
    // 2xx 范围内的状态码都会触发该函数。
    // 对响应数据做点什么
    return response.data
  }, (error)=> {
    // 超出 2xx 范围的状态码都会触发该函数。
    // 对响应错误做点什么
    // 监控401 token失效
    console.dir(error)
    if(error.response.status === 401){
      removeToken()
      router.navigate('/login')
      window.location.reload()
    }
    return Promise.reject(error)
})

Echarts基础图表实现
#

为了实现我们要在项目中接入第三方的图标插件，看文档很重要。

首先进行安装：

npm install echarts

然后查看Echarts的一系列示例，然后进行更改。但是直接拿来用是会有bug的，因为直接写不能避免dom不可用这种情况的发生！！！

什么是DOM？

DOM（Document Object Model，文档对象模型） 是 浏览器解析HTML页面时，创建的对象结构。它将网页转换成一个JavaScript可操作的树状结构，使我们可以通过javascript动态操作HTML和CSS。

简单来说：

HTML是网页的结构（代码）。

DOM是HTML在浏览器内存中的对象表示（可操作）。

DOM是如何工作的？

浏览器渲染网页时，通常会经历以下步骤：

  1. 解析HTML，生成DOM树
  2. 解析CSS，生成CSSOM（CSS Object Model）
  3. 合并DOM和CSSOM，生成渲染树
  4. 布局（Layout），计算元素的大小和位置
  5. 绘制（Painting），渲染到屏幕

在JavaScript代码执行之前，DOM可能还没完全构建完成，这就是为什么会出现 “DOM不可用” 的情况。

因此我们可以使用useEffect来保证dom可用的情况下，才进行图标的渲染。同时要注意，dom节点需要有宽高！！不然的话图表是没有办法渲染出来的。

相关实现的代码：

import * as echarts from 'echarts';
import { useEffect } from 'react';

const Home = () => { 
    useEffect(() => {
        //保证dom可用 才进行图标的渲染
        //获取渲染图表的dom节点
        const chartDom = document.getElementById('main')

        //图表初始化生成图表实例对象
        const myChart = echarts.init(chartDom)

        //准备图表参数
        const option = {
        xAxis: {
            type: 'category',
            data: ['Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat', 'Sun']
        },
        yAxis: {
            type: 'value'
        },
        series: [
            {
            data: [120, 200, 150, 80, 70, 110, 130],
            type: 'bar'
            }
        ]
        }

        //使用图表参数完成图表的渲染
        option && myChart.setOption(option)
    },[])

    return <div><div id='main' style={{width:'500px', height:'400px'}}></div></div>
}

export default Home

上面的代码用了原生的dom操作，当然我们也可以用react里面的dom操作，用钩子函数useRef即可。

Echarts组件封装实现
#

封装解决复用问题，把需要图表中特殊化的部分抽象成props参数做适配。

就近原则，在Home文件夹下新建components文件夹来存储。构建一个柱状图组件，把功能代码都放到组件中，把可变的部分抽象成prop参数。

抽象成了一个小组件，title是我们的参数：

//柱状图组件
//把功能代码都放到组件中
//把可变的部分抽象成prop参数
import * as echarts from 'echarts';
import { useEffect, useRef } from 'react';

const BarChart = ({title}) => {
    const chartRef = useRef(null)
    useEffect(() => {
        //保证dom可用 才进行图标的渲染
        //获取渲染图表的dom节点
        const chartDom = chartRef.current

        //图表初始化生成图表实例对象
        const myChart = echarts.init(chartDom)

        //准备图表参数
        const option = {
        title:{
            text: title
        },
        xAxis: {
            type: 'category',
            data: ['vue','React','Angular']
        },
        yAxis: {
            type: 'value'
        },
        series: [
            {
            data: [10,40,70],
            type: 'bar'
            }
        ]
        }

        //使用图表参数完成图表的渲染
        option && myChart.setOption(option)
    },[])

    return <div ref={chartRef} style={{width:'500px', height:'400px'}}></div>
}

export default BarChart

封装API模块
#

目前为止的各种请求都是在当前功能的位置，不利于后期维护，合理的做法应该把这些分散维护的接口请求统一装到apis文件夹里面，方便维护。

这里的思路是把项目中的所有接口按照业务模块以函数的形式统一封装到apis模块中。

//用户相关的所有请求
import { request } from "@/utils";

//登录请求
export function loginAPI(formData){
    return request({
        url:'/authorizations',
        method:'POST',
        data: formData
    })
}

//获取用户信息
export function getProfileAPI(){
    return request({
        url:'/user/profile',
        method:'GET'
    })
}

这次我选择自定义业务hook方法，主要流程：

  1. 创建一个use打头的函数
  2. 在函数中封装业务逻辑，并return出组件中要用到的状态数据

//封装获取频道列表的逻辑
import {useEffect, useState} from 'react'
import { getChannelAPI } from '@/apis/article'

function useChannel(){
    //获取频道列表中的所有逻辑
    const [channelList, setChannelList] = useState([])

    //封装函数 函数内调用接口
    const getChannelList = async () => {
        const res = await getChannelAPI()
        setChannelList(res.data.channels)
    }
    
    useEffect(() => {
        //调用函数
        getChannelList()
    }, [])

    //把组件中要用到的数据return出去
    return {
        channelList
    }
}

export { useChannel }

在这里我一开始有个问题：为什么useEffect的依赖项要写[articleId, form]？

react的规则是：useEffect必须显式声明它所依赖的所有变量，否则可能导致数据不同步或潜在bug。

配置路由懒加载
#

路由懒加载是指路由的JS资源只有在被访问时才会动态获取，目的是为了优化项目首次打开的时间。

说白话就是，只有用到了某个路由才去加载它的资源：

如何进行配置？

  1. 把路由修改为由React提供的lazy函数进行动态导入
  2. 使用React内置的Suspense组件包裹路由中element选项对应的组件

改进后的route代码：

//路由配置
import Layout from "@/pages/Layouts";
import Login from "@/pages/Login";
import {createBrowserRouter} from 'react-router-dom'
import {AuthRoute} from '@/components/AuthRoute'
// import Home from "@/pages/Home";
// import Article from "@/pages/Article";
// import Publish from "@/pages/Publish";
import { lazy, Suspense } from "react";

//借助lazy函数对组件进行导入
const Home = lazy(() => import('@/pages/Home'))
const Article = lazy(() => import('@/pages/Article'))
const Publish = lazy(() => import('@/pages/Publish'))

//配置路由实例
const router = createBrowserRouter([
    {
        path:"/",
        element:<AuthRoute><Layout /></AuthRoute>,
        children:[
            {
                path:'/',
                index: true,
                element:<Suspense fallback={'加载中...'}><Home/></Suspense>
            },
            {
                path:'article',
                element:<Suspense fallback={'加载中...'}><Article/></Suspense>
            },
            {
                path:'publish',
                element:<Suspense fallback={'加载中...'}><Publish/></Suspense>
            },
        ]
    },
    {
        path:"/login",
        element:<Login />
    },
])

export default router

CDN优化
#

什么是CDN？

CDN是一种内容分发网络服务，当用户请求网站内容时，由离用户最近的服务器将缓存的资源内容传递给用户。

哪些资源可以放到CDN服务器？

体积较大的非业务JS文件，比如react、react-dom：

  1. 体积较大，需要利用CDN文件在浏览器的缓存特性，加快加载时间
  2. 非业务JS文件，不需要经常做变动，CDN不用频繁更新缓存

项目中怎么做？

  1. 把需要做CDN缓存的文件排除在打包之外（react、react-dom）
  2. 以CDN的方式重新引入资源（react、react-dom）
