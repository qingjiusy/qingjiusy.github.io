初步构建项目

初始化
#

命令行：

npx create-react-app 项目名
npm run start

SCSS是一种后缀名为.scss的预编译CSS语言，支持一些原生CSS不支持的高级用法，比如变量使用，嵌套语法等，使用SCSS可以让样式代码更加高效灵活。

安装scss：

npm install sass -D

安装Ant Design组件库，Ant Design是由蚂蚁金服出品的社区使用最广的React PC端组件库，内置了常用的现成组件，可以帮助我们快速开发PC管理后台项目：

npm install antd --save

安装路由包react-router-dom：

npm i react-router-dom

同时也配置好别名路径，首先要安装相关包：

npm i @craco/craco -D

然后也别忘记新建jsconfig.json和craco.config.js去进行配置。

安装axios库：

npm i axios

安装redux相关库：

npm i react-redux @reduxjs/toolkit

构建登录界面
#

首先在ui设计上主要就是依靠antD来实现基础的demo。

表单校验可以在提交登录之前校验用户的输入是否符合预期，如果不符合就阻止提交，显示错误信息。在表单校验的实现中，用FormItem绑定name以及rules(根据官方文档来写)。

我们要实现的业务功能有：

  • 增加失焦时校验
  • 手机号为有效格式

失焦时校验主要是依靠Form中的validateTrigger属性来实现的：

validateTrigger="onBlur"

在这里我们用了onBlur，表示在失焦的时候去校验。

之后关于手机号的校验，我们主要是依靠Form中的rules来规定，在这里我们使用正则表达式/^1[3-9]\d{9}$/来实现。

获取表单数据
#

显然当用户输入了正确的表单数据，比如在这里就是针对的验证码的界面的时候，我们需要收集用户当前输入的内容，用来提交接口请求。

查看官方文档，可知这里是主要利用Form组件绑定onFinish回调函数来实现。

在这种情况下： <Form onFinish={onFinish} validateTrigger="onBlur">，通过了验证后会自动调用onFinish函数，获取表单中的数据，方便了很多。

登录-封装request请求模块
#

整个项目会用到很多网络请求，所以使用axios来做好封装是比较利于统一管理的。

axios的封装处理：

  1. 根域名配置
  2. 超市时间
  3. 请求拦截器 / 相应拦截器

请求拦截器：

http.interceptors.request.use((config)=> {
    return config
  }, (error)=> {
    return Promise.reject(error)
})

在请求拦截器中，在每次发送 HTTP 请求前先做拦截，然后可以插入一些自定义的配置，比如对于参数的处理。比如在这里接受两个回调，一个是成功一个是失败。

响应拦截器

http.interceptors.response.use((response)=> {
    // 2xx 范围内的状态码都会触发该函数。
    // 对响应数据做点什么
    return response.data
  }, (error)=> {
    // 超出 2xx 范围的状态码都会触发该函数。
    // 对响应错误做点什么
    return Promise.reject(error)
})

这是在响应返回到客户端之前做拦截，然后处理。

之后会在这两个拦截器中间重点处理返回的数据，做业务开发。

为了方便复用共享，使用redux来管理token。

  1. redux中编写获取token的异步获取和同步修改
  2. login组件负责提交action并且把表单数据传递过来

之后就是经典的redux设置部分，以及异步的获取：

const fetchLogin = (loginForm) => {
    return async (dispatch)=>{
        //发送异步请求
        const res = await request.post('/authorizations', loginForm)
        //提交同步action进行token存入
        dispatch(setToken(res.data.token))
    }
}

登录-实现token的持久化
#

现存问题：redux存入了token之后用如果刷新浏览器，token会丢失（持久化就是防止刷新时丢失token）。

通过观察f12中redux的state，可以看到一刷新就丢失了。

问题原因是redux是基于浏览器内存的储存方式，刷新时状态恢复为初始值。也就是这里：

initialState:{
        token:''
    },

实现方案是配合localStorage去实现:

要注意，在现实开发中，这种方法其实占到了95%以上！！

一般来说，在实际的开发中的用户登录流程：

首次的时候：用户前端输入，然后后端验证返回token，前端去存到localstorage 接下来，前端直接拿到本地的token发给后端验证

封装token的存取删方法
#

为什么要封装呢？

因为对于token的各类操作在项目中多个模块中都有用到，为了共享复用我们可以直接把它封装成工具函数。

之后就可以在其他地方复用这些工具函数了，如下：

//封装和token有关的方法 存 取 删
const TOKENKEY = 'token_key'
function setToken(token) {
    localStorage.setItem(TOKENKEY, token)
}

function getToken() {
    return localStorage.getItem(TOKENKEY)
}

function removeToken() {
    localStorage.removeItem(TOKENKEY)
}

export {
    setToken,
    getToken,
    removeToken
}

axios请求头注入token
#

Token作为用户的一个标识数据，后端很多接口都会以它作为接口权限判断的依据；请求拦截器注入Token之后，所有用到Axios实例的接口请求都自动携带了Token。

方法：

  • Axios请求拦截器请求头中注入Token
  • 调用接口测试Token是否成功携带

实现后的请求拦截器, 注意这里要配合后端写的代码：

// 添加请求拦截器
request.interceptors.request.use((config)=> {
  //操作config 注入token数据
  const token = getToken()
  if(token){
    config.headers.Authorization = `Bearer ${token}`
  } 
    return config
  }, (error)=> {
    return Promise.reject(error)
})

config.headers.Authorization这个写法是由axios决定的，而Bearer ${token}这个拼接写法是由后端来决定好的。

使用token做路由权限的控制
#

有些路由页面内的内容信息比较敏感，如果用户没有经过登录获取到有效Token，是没有权限跳转的，根据Token的有无控制当前路由是否可以跳转就是路由的权限控制。

import { getToken } from "@/utils"
import { Navigate } from "react-router-dom"

function AuthRoute({children}) {
    const token = getToken()
    if(token) {
        return <>{children}</>
    } else {
        //用一个重定向组件
        return <Navigate to={'/login'} replace/>
    }
}

很显然，在这里有token就和之前的写法一样，没有token就直接重定向到登录界面。

html,
body {
  margin: 0;
  height: 100%;
}

#root {
  height: 100%;
}

其中注意要先把html和body撑到100%，再让他们的子元素root撑满到100%，才能保证root中的内容真的撑满整个屏幕。

现在要去点击左侧菜单可以跳转到对应的目标路由。

在这里，重要的是去用useNavigate钩子函数去实现跳转！这个onMenuClick函数在Menu组件中被使用。

const navigate = useNavigate()
const onMenuClick = (route) => {
const path = route.key
navigate(path)
}

退出登录实现
#

退出是一个很常见的通用业务逻辑，一般来说退出登录要做什么？

必要通用的退出业务逻辑：

  1. 提示用户是否确认要退出（危险操作，二次确认）
  2. 用户确认之后清除用户信息（Token以及其它个人信息）
  3. 跳转到登录页（为下次登录做准备）

redux中要新增一个清除信息的action:

clearUserInfo(state){
            state.token = ''
            state.userInfo = {}
            removeToken()
        }

在退出的按钮上实现的操作：

const onConfirm = () => { 
    dispatch(clearUserInfo())
    navigate('/login')
}

处理token失效
#

什么是Token失效？

为了用户的安全和隐私考虑，在用户长时间未在网站中做任何操作且规定的失效时间到达之后，当前的Token就会失效，一旦失效，不能再作为用户令牌标识请求隐私数据。

前端如何知道Token已经失效了？

通常在Token失效之后再去请求接口，后端会返回401状态码，前端可以监控这个状态做后续的操作

Token失效了前端做什么？

  1. 在axios拦截中监控401状态码
  2. 清除失效Token，跳转登录

实现这些操作的响应拦截器：

request.interceptors.response.use((response)=> {
    // 2xx 范围内的状态码都会触发该函数。
    // 对响应数据做点什么
    return response.data
  }, (error)=> {
    // 超出 2xx 范围的状态码都会触发该函数。
    // 对响应错误做点什么
    // 监控401 token失效
    console.dir(error)
    if(error.response.status === 401){
      removeToken()
      router.navigate('/login')
      window.location.reload()
    }
    return Promise.reject(error)
})

Echarts基础图表实现
#

为了实现我们要在项目中接入第三方的图标插件，看文档很重要。

首先进行安装：

npm install echarts

然后查看Echarts的一系列示例，然后进行更改。但是直接拿来用是会有bug的，因为直接写不能避免dom不可用这种情况的发生！！！

什么是DOM？

DOM（Document Object Model，文档对象模型） 是 浏览器解析HTML页面时，创建的对象结构。它将网页转换成一个JavaScript可操作的树状结构，使我们可以通过javascript动态操作HTML和CSS。

简单来说：

HTML是网页的结构（代码）。

DOM是HTML在浏览器内存中的对象表示（可操作）。

DOM是如何工作的？

浏览器渲染网页时，通常会经历以下步骤：

  1. 解析HTML，生成DOM树
  2. 解析CSS，生成CSSOM（CSS Object Model）
  3. 合并DOM和CSSOM，生成渲染树
  4. 布局（Layout），计算元素的大小和位置
  5. 绘制（Painting），渲染到屏幕

在JavaScript代码执行之前，DOM可能还没完全构建完成，这就是为什么会出现 “DOM不可用” 的情况。

因此我们可以使用useEffect来保证dom可用的情况下，才进行图标的渲染。同时要注意，dom节点需要有宽高！！不然的话图表是没有办法渲染出来的。

相关实现的代码：

import * as echarts from 'echarts';
import { useEffect } from 'react';

const Home = () => { 
    useEffect(() => {
        //保证dom可用 才进行图标的渲染
        //获取渲染图表的dom节点
        const chartDom = document.getElementById('main')

        //图表初始化生成图表实例对象
        const myChart = echarts.init(chartDom)

        //准备图表参数
        const option = {
        xAxis: {
            type: 'category',
            data: ['Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat', 'Sun']
        },
        yAxis: {
            type: 'value'
        },
        series: [
            {
            data: [120, 200, 150, 80, 70, 110, 130],
            type: 'bar'
            }
        ]
        }

        //使用图表参数完成图表的渲染
        option && myChart.setOption(option)
    },[])

    return <div><div id='main' style={{width:'500px', height:'400px'}}></div></div>
}

export default Home

上面的代码用了原生的dom操作，当然我们也可以用react里面的dom操作，用钩子函数useRef即可。
