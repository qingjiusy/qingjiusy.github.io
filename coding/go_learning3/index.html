项目架构图
#

上面的是项目的架构图，主要重要的就是server（服务器）和client（用户），两者之间会进行通信，而server中重要的两个属性/数据结构就是OnlineMap（主要记录当前系统中的用户在线）和channel（server用来广播的channel，能够把消息给每一个客户端来广播）

其中handler go是一个读的go，user中另一个channel是写的goroutine，它是一个读写分离模型。

基础server构建
#

编写server类
#

首先就是构建server类以及创建server的构造函数：

type Server struct {
	Ip   string
	Port int
}

// 创建一个server的构造函数
func NewServer(ip string, port int) *Server {
	//把当前对象的地址给server
	server := &Server{
		Ip:   ip,
		Port: port,
	}

	//传回指针
	return server
}

然后实现服务器相关功能，我们首先实现函数来启动一个 TCP 服务器：

func (this *Server) Start() {
    // 1. 启动 TCP 监听
    listener, err := net.Listen("tcp", fmt.Sprintf("%s:%d", this.Ip, this.Port))
    //如果报错则详细输出
    if err != nil {
        fmt.Println("net.Listen err:", err)
        return
    }

    // 2. 确保在函数结束时关闭监听器
    defer listener.Close()

    // 3. 持续接受客户端连接
    for {
        // 3.1 接受新的客户端连接
        conn, err := listener.Accept()
        if err != nil {
            fmt.Println("listener accept err:", err)
            continue
        }

        // 3.2 启动一个新的 goroutine 处理连接
        go this.Handler(conn)
    }
}

对其中这一段代码稍作解释：listener, err := net.Listen("tcp", fmt.Sprintf("%s:%d", this.Ip, this.Port))

首先查看net.Listen()的函数定义：func Listen(network, address string) (net.Listener, error)

其中network：指定协议类型，常见的有"tcp", “tcp4”, “tcp6”, “udp"等。这里是"tcp”。

address：监听的 IP 地址和端口，例如"127.0.0.1:8080"。fmt.Sprintf()是格式化字符串，在这里我们用this.Ip, this.Port得到了地址。

最后的这个部分：

for {
        // 3.1 接受新的客户端连接
        conn, err := listener.Accept()
        if err != nil {
            fmt.Println("listener accept err:", err)
            continue
        }

        // 3.2 启动一个新的 goroutine 处理连接
        go this.Handler(conn)
    }

是一个典型的TCP服务器接受客户端连接并处理请求的部分。它主要完成以下两个关键功能：

  1. 接受新的客户端连接(listener.Accept())
  2. 启动新的Goroutine处理连接(go this.Handler(conn))

用户上线的功能
#

一个user类应该表示一个客户端。而onlineMap应该记录当前应该有哪些user在线，其中的key应该是用户名，value应该是当前用户的对象。

为了通信，每个用户对象都会绑定一个channel，channel是专门用来向user对应的客户端发送消息的。每个user内部应该都有一个goroutine不断阻塞监听channel中是否有数据，一旦有数据就应该拿出来发送到客户端client中。

而Message其实就是server中的一个channel，它是用来把消息进行广播的。如果当前有一个消息需要每一个client都需要收到的话，那么这个消息我们需要通过Message进行广播。

显然需要有一个goroutine一直监听这个Message管道，如果channel中有数据，那么就要遍历这个onlineMap，把Message管道中的消息发给各个user的channel。这样就实现了广播效果。

用户上线：

先是conn链接到server，告知用户上线，然后onlineMap要创建对应的新用户以及user对象。最后要把这个新用户上线的消息进行广播。

用户部分代码
# 

package main

import "net"

type User struct {
	Name string
	Addr string
	C    chan string
	conn net.Conn //表示当前user可以和server通信的一个客户端链接
}

//创建一个用户的API
func NewUser(conn net.Conn) *User {
	userAddr := conn.RemoteAddr().String() //拿到这个客户端地址

	user := &User{
		Name: userAddr,
		Addr: userAddr,
		C:    make(chan string),
		conn: conn,
	}

	//启动监听当前user channel消息的goroutine
	go user.ListenMessage()

	return user
}

//监听当前user channel的go方法，一旦有消息就直接发送给对端客户端
func (this *User) ListenMessage() {
	for {
		msg := <-this.C

		this.conn.Write([]byte(msg + "\n"))
	}
}

主要就是相关的创建user的构造函数和一个user监听channel的方法。

服务端部分代码
#

首先就是更新我们的server的内容，要有两个重要的属性需要加入：一个就是OnlineMap，另一个就是Message这个channel。

type Server struct {
	Ip   string
	Port int

	//在线用户的列表
	OnlineMap map[string]*User
	mapLock   sync.RWMutex

	//消息广播的channel
	Message chan string
}

// 创建一个server的构造函数
func NewServer(ip string, port int) *Server {
	//把当前对象的地址给server
	server := &Server{
		Ip:        ip,
		Port:      port,
		OnlineMap: make(map[string]*User),
		Message:   make(chan string),
	}

	//传回指针
	return server
}

然后就是完善Handler函数，它应对的就是当conn发生时需要产生的一系列操作：

func (this *Server) Handler(conn net.Conn) {
	//...当前链接的业务
	// fmt.Println("链接建立成功")

	//首先有了conn应该先创建一个user
	user := NewUser(conn)

	//用户上线，首先就是将用户加入到OnlineMap中
	this.mapLock.Lock()
	this.OnlineMap[user.Name] = user
	this.mapLock.Unlock()

	//广播当前用户上线消息
	this.BroadCast(user, "已经上线了")

	//当前handler阻塞
	select {}
}

其中这里的这个部分：

this.mapLock.Lock()
this.OnlineMap[user.Name] = user
this.mapLock.Unlock()

这是一个典型的Go并发控制代码段，用于安全地向OnlineMap添加一个新的用户(user)。

this.mapLock.Lock()会尝试获取mapLock这个互斥锁。 如果锁已经被其他Goroutine占用，会阻塞当前Goroutine，直到锁可用。 这样就确保了接下来的OnlineMap操作是线程安全的，避免数据竞争。

this.OnlineMap[user.Name] = user显然就是将用户对象(user)添加到OnlineMap中。

this.mapLock.Unlock()则是释放互斥锁，允许其他Goroutine继续访问OnlineMap。 结束临界区(critical section)，减少锁竞争，提高程序并发性能。

还有要注意这里的**select {}**部分，这是一种简单偷懒的写法（实际工作不那么写），是为了不使这个goroutine结束，强行让它存活才那么写的。

理由是因为一旦这个go程结束，会导致**这个客户端对应的conn关闭，客户端也会断开连接。**无法实现后续的广播。

同时注意到，既然已经有了Message管道，那么肯定得有监听这个管道的go程来实现广播数据的最后一步。

// 监听Message广播消息channel的goroutine，一旦有消息就发送给全部的在线user
func (this *Server) ListenMessager() {
	for {
		msg := <-this.Message

		//将msg发送给全部的在线User
		this.mapLock.Lock()
		for _, cli := range this.OnlineMap {
			cli.C <- msg
		}
		this.mapLock.Unlock()
	}
}

就这样实现了广播用户上线消息。

用户消息广播功能
#

在这里我们在handle函数里面实现了一个用户消息广播功能。主要是下面这一段：

go func() {
		buf := make([]byte, 4096)
		for {
			n, err := conn.Read(buf)
			if n == 0 {
				this.BroadCast(user, "offline")
				return
			}

			if err != nil && err != io.EOF {
				fmt.Println("Conn Read err:", err)
				return
			}

			//提取用户的消息（同时靠切片来去除\n）
			msg := string(buf[:n-1])

			//将得到的消息进行广播
			this.BroadCast(user, msg)
		}
	}()

在这里，利用了缓冲区(buf)和conn.Read来从客户端读取数据。

在Go的网络编程中，缓冲区(buf)是一个用于临时存储从网络连接(conn)读取到的数据的内存区域。它的作用主要是提高数据传输效率，减少系统调用次数，并简化数据处理。

在代码中，缓冲区的定义如下: buf := make([]byte, 4096) make([]byte, 4096)创建了一个长度为4096字节的字节切片（byte slice）。 []byte是Go中最常见的二进制数据结构，用于存储原始数据（例如网络数据、文件数据）。

conn.Read(buf)是一个阻塞函数，尝试从TCP连接conn读取数据，并将数据填充到缓冲区buf中 conn.Read(buf)是一个阻塞调用，但它并不会立即读取你输入的每一个字符，而是基于TCP数据流的缓冲机制。

假设你在客户端输入 123456\n，以下是典型的数据传输过程：

缓冲区等待：

你输入 1 后，数据并不会立即发送到服务端，而是暂存在客户端的发送缓冲区。

只有当缓冲区满了，或者你输入了换行（Enter）或手动发送时，数据才会被发送到服务器。

数据到达服务端：

服务端的TCP缓冲区接收到数据，触发conn.Read(buf) 读取该缓冲区的数据。

一次性读取：

如果缓冲区内的数据小于buf的大小（4096），那么一次Read调用会读取所有可用的数据，例如 123456。

以及相关业务封装：

//用户的上线业务
func (this *User) Online() {

	//用户上线,将用户加入到onlineMap中
	this.server.mapLock.Lock()
	this.server.OnlineMap[this.Name] = this
	this.server.mapLock.Unlock()

	//广播当前用户上线消息
	this.server.BroadCast(this, "online")
}

//用户的下线业务
func (this *User) Offline() {

	//用户下线,将用户从onlineMap中删除
	this.server.mapLock.Lock()
	delete(this.server.OnlineMap, this.Name)
	this.server.mapLock.Unlock()

	//广播当前用户上线消息
	this.server.BroadCast(this, "offline")
}

//用户处理消息的业务
func (this *User) DoMessage(msg string) {
	this.server.BroadCast(this, msg)
}

在线用户查询
#

用户查询目前所有在线的用户，并且只在希望查询用户的那个client显示查询结果，假设我们用"who"指令表示查询：

//给当前User对应的客户端发送消息
func (this *User) SendMsg(msg string) {
	this.conn.Write([]byte(msg))
}

//用户处理消息的业务
func (this *User) DoMessage(msg string) {
	if msg == "who" {
		//查询当前在线用户都有哪些

		this.server.mapLock.Lock()
		for _, user := range this.server.OnlineMap {
			onlineMsg := "[" + user.Addr + "]" + user.Name + ":" + "在线...\n"
			this.SendMsg(onlineMsg)
		}
		this.server.mapLock.Unlock()

	} else {
		this.server.BroadCast(this, msg)
	}
}

超时强踢功能
#

在这里我们运用定时器来实现超时强踢功能，使用的关键代码就是：time.After(time.Second * 10)

改进后的handler函数：

func (this *Server) Handler(conn net.Conn) {
	//...当前链接的业务
	// fmt.Println("链接建立成功")

	//首先有了conn应该先创建一个user
	user := NewUser(conn, this)

	user.Online()

	//监听用户是否活跃的channel
	isLive := make(chan bool)

	//接受客户端发送的消息
	go func() {
		buf := make([]byte, 4096)
		for {
			n, err := conn.Read(buf)
			if n == 0 {
				user.Offline()
				return
			}

			if err != nil && err != io.EOF {
				fmt.Println("Conn Read err:", err)
				return
			}

			//提取用户的消息（同时靠切片来去除\n）
			msg := string(buf[:n-1])

			//将得到的消息进行广播
			user.DoMessage(msg)

			//用户的任意消息，代表当前用户是一个活跃的
			isLive <- true
		}
	}()

	//当前handler阻塞
	//当前handler阻塞
	for {
		select {
		case <-isLive:
			//当前用户是活跃的，应该重置定时器
			//不做任何事情，为了激活select，更新下面的定时器

		case <-time.After(time.Second * 10):
			//已经超时
			//将当前的User强制的关闭

			user.SendMsg("你被踢了")

			//销毁用的资源
			close(user.C)

			//关闭连接
			conn.Close()

			//退出当前Handler
			return //runtime.Goexit()
		}
	}
}

在这里可以看到有两个for，对应着两个go程。它们是并发执行的。

goroutine 1（接收消息）：

  • 持续监听客户端消息。
  • 处理消息并发送活跃信号到isLive。
  • 如果客户端断开连接或发生读取错误，会终止自己。

goroutine 2（活跃检测）：

  • 主要是一个select 循环，不断监听活跃信号和超时事件。
  • <-isLive: 只要有活跃信号，就什么都不做，只是重置定时器。
  • <-time.After(): 超时后执行踢出和连接清理。

所有消息在客户端自动显示的原因
#

PowerShell 客户端实际上是一个TCP客户端，当它连接到服务器时，服务器会通过conn.Write()直接将消息写入这个TCP连接，PowerShell会自动将接收到的数据显示到终端上。

虽然没有在服务器端显式调用Read()来处理客户端的回应，但客户端会自动显示来自服务器的消息，因为消息是直接通过Write()发送到TCP连接的，PowerShell终端会自动显示这些传入的数据。

你看到消息在PowerShell终端显示的流程是：

  1. Server通过BroadCast()将消息发送到每个User的C channel。
  2. 每个User在独立的ListenMessage() goroutine中不断监听C channel并将消息写入客户端的TCP连接(conn.Write()).
  3. PowerShell作为TCP客户端会自动显示收到的消息数据。
