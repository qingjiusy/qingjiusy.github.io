#

#

A

题型
#

识别信号
#

要找到「不重复」且和为 0 的三元组，最简单的就是三重循环。但是不重复我们应该联想到排序，排序以后我们遍历数组，假设遍历的是idx，我们剩下的任务就是去找两个数让他们加上idx的数，总和为0。

核心思路
#

不重复引导我们排序，同时排序后我们要去以三数之和为一个标的去找可能的组合。那么我们就可以有两个在端点的指针，如果总数和小了，就移动left指针去增加总和；如果总数和大了，就移动right指针去减小总数和。

实现要点
#

我们遍历排序后的数组，假设现在遍历到idx，left指针应该从idx右边开始，right指针应该从数组末尾开始。 当left大于等于right或者idx的右边剩下不到两个元素了，我们的遍历也就结束了。 同时为了不重复，我们要注意在每一次找到正确答案的时候更新后进行重复性检查。 同时我们对idx也要进行去重。

易错点
#

注意这里的去重很容易做错。 首先明确，left/right 的去重只能在找到一组答案并移动指针后进行，避免更新后的参数和之前的参数一样，被我们再次记录。 在去重的时候，只能对刚移动过的指针做去重，不能没移动 left 却因为 left 重复就把它跳过，比如[-1,0,0,1,2,3]。我们如果idx=-1,left=0,right=3，这时候不正确，我们更新参数但是发现left还是0，这时候如果对left去重，让他向右移动，我们就错过了我们的答案。 去重主要有两个时机：

  1. 遍历 idx 时，如果当前数和前一个固定数一样，直接跳过
  2. 每次找到正确答案更新后的去重，是去对对比刚刚被使用过的 left/right 值。比如[-2, 0, 1, 1, 2]，我们找到了[-2, 0, 2]这一组答案以后，如果错误的对未来的元素进行去重分析，我们会认为[1, 1]这一段重复了。然后移动left和right指针，让right < left故而产生错误。

复杂度（可选）
#

O(N^2) idx移动的复杂度是O(N)，对于每个移动好的idx，我们在里面去做双指针移动的复杂度是O(N)。虽然有排序，但是排序复杂度O(NlogN)小于O(N^2)。

42. 接雨水 Trapping Rain Water
#

熟悉程度
#

B

题型
#

相向双指针 或者 动态规划 或者 单调栈

识别信号
#

做法一（复杂度最低）： 一道经典题，直接记忆。 每个位置能接多少水，取决于它左侧最高墙和右侧最高墙中的较小值。

做法二： 有点类似于 84. 柱状图最大的矩形，每个元素只有找到左右两边第一个比自己高的柱子，才能确定这个元素中能接的水面高度。这个思路提示我们使用单调栈。

核心思路
#

做法一： 以每个长度为1的底（也就是单个元素）作为一个单位，一个个来看每个元素能接的雨水的量。每个单位位置能接的水 = 底边（固定为1）* 接水高度（min（左边所有元素的最高值，右边所有元素的最高值））。移动元素计算出一个个元素对应的左边元素最高值和右边元素最高值这个方法，可以让我们想到用动态规划来解答。 但是在这里我们可以进一步优化，尝试使用双指针来解答。因为可以显然注意到维护左边或者右边元素的最大值这个数组是有点冗余的，我们可以考虑去用双指针＋leftmax和rightmax两个参数来完成这件事。 我们从left，right两个指针中来选择接下来移动哪个位置，如果leftmax < rightmax，我们就可以确定left处的积水量；反之亦然。

为什么呢？ 因为对于此时的left的来说，左边的屏障是已经确定的，一定是leftmax；右边起码是大于等于rightmax，只是没确定一个特定的值。但是现在leftmax < rightmax，所以无论如何left这个位置的水不会从右边流走，left位置的储水量就是leftmax - height[left]

做法二： 我们对于每个元素都要去找它对应的左右的第一个比自己高的柱子，提示我们使用单调递减栈，如果我们检查到的元素大于目前栈顶中下标对应的元素，我们就弹出栈顶，去计算出栈元素作为凹槽底部，用左右边界的较小值减去底部高度得到本层水高，横着接的雨水有多少。然后循环这个过程，直到栈顶中下标元素大于目前检查到的元素或者栈空了，我们就入栈此下标。

实现要点
#

做法一： 我们对比leftmax和rightmax，通过大小对比移动哪个位置。如果相同，则移动左边右边都可以。 终止条件是left和right重合了。 每次更新后，不仅更新left或者right，还要去更新对应的leftmax或者rightmax。

做法二： 注意在横向的接每一块的雨水的时候，具体那一块的雨水的大小是这样的：

bottom = height[stack.pop()]
if(not stack):
    break

left = stack[-1]
right = i
ans += (min(height[left], height[right]) - bottom) * (right - left - 1)

在代码中如果我们发现栈空了，说明这个出栈元素没有左边界，直接break即可。

易错点
#

做法一： 要去理解好更新的条件，注意是去对比leftmax和rightmax来决定移动left还是right，而不是去比较left和right。

做法二： 一开始做这题我想要像 84. 柱状图最大的矩形 那题那样前后加 0，但它们基本没什么作用。无法像 84 那样帮你处理边界。因为栈中如果仍然存有元素，本身就说明这些元素是没有右边界的，接不到雨水。

复杂度（可选）
#

双指针法： 时间复杂度 O(N) 空间复杂度 O(1)

单调栈法： 时间复杂度 O(N) 空间复杂度 O(N) 需要维护一个单调栈

动态规划： 时间复杂度 O(N) 空间复杂度 O(N)

做法二：单调队列

识别信号
#

做法一： 移动窗口来快速寻找窗口中的最大值，本身就是适合大根堆的特性，寻找最大值特别方便。

做法二： 因为要求出窗口中的最大值并且窗口逐元素移动，可以考虑使用单调队列。

核心思路
#

做法一： 首先实现大根堆，每次要计算窗口中最大值时，就用看大根堆的heap[0]。但是堆虽然找最大值比较好找，删除一个任意元素则要花较长时间。因此我们在堆中存放的不仅是数字，应该是一个元组，是（index位置的数字，index），这样我们在试图提取最大值时，假如此时的右边界是right，窗口左边界就是right-k+1，先去判定一下这个元素还在不在我们的窗口里面，如果不在就直接pop就好，然后继续提取我们的最大值。

做法二： 首先要想明白，对于一个窗口中的index i和j来说，我们假设i < j，如果nums[i] < nums[j]的情况下，只要窗口中的index包含了j，那么起码一定不会去取nums[i]，它是可以直接被丢弃的。从这个角度出发，我们需要维护一个单调递减队列。一旦新加入的元素大于单调队列中的尾部元素，我们就可以直接丢弃尾部元素，因为它绝对不会被使用。 同时我们最后在获取答案时是从单调递减队列的左边（也就是队列的最大值）来找，我们在这个时候去判断这个最左端的元素还在不在我们的窗口内，如果不在了就pop它，继续检查我们单调队列的新的最左端元素。

实现要点
#

做法一： 在python中，堆其实底层是由list实现的，并且只支持小根堆。因此我们使用大根堆时，把元素取负放入小根堆即可。另外对于其中元素是（x，y）元组的堆来说，是根据x来进行堆的构造的。

做法二： 在python，单调队列常常要使用双端队列来完成，因为我们在要两端加入和删除元素，因此使用deque()。 先清理队尾较小元素，再把right入队；窗口形成后，清理过期队头，再记录nums[deque[0]]。

复杂度（可选）
#

做法一： 时间复杂度 O(NlogN) 因为将一个元素放入优先队列的时间复杂度是O(logN) 空间复杂度 O(N) 因为延迟删除，堆的占用空间就是O(N)

做法二： 时间复杂度 O(N) 空间复杂度 O(K) 因为我们每次移动指针，都会弹出不在窗口中的元素，deque的长度不会超过K

核心思路
#

  2. 如果看到s[index]的字符是字母或者"["，则直接放入栈中
  3. 如果看到s[index]的字符是"]"，我们则开始pop栈中的内容，首先pop出来的肯定是一系列字母，我们一直pop到它直到遇到"[“为止，意为我们得到了这个括号内的所有字母了，然后我们保证字母串是正确的顺序（用reverse()）反转，然后用接下来pop出的数字去乘上这个字母串。接下来最重要的是我们要去把这个字母串重新入栈！（因为我们仍然可能在别的括号内）

当我们遍历完栈之后，按顺序输出即可

739. 每日温度 Daily Temperatures
#

熟悉程度
#

B

题型
#

单调栈

识别信号
#

对每个位置，都要找它右边第一个比它大的元素。这种找下一个更大/更小元素，属于单调栈的经典题型。

核心思路
#

我们构建一个单调栈，针对这种寻找下一个更大/更小元素的单调栈解题思路，我们要存的一般都是下标。原因是单调栈通常不只是想知道“下一个更大元素是多少”，还经常需要知道：它距离当前元素多远，它的位置在哪里，或者用这个位置计算区间长度、面积等… 比如这一题就是找到下一个位置距离当前位置有多远。 我们构建一个单调栈，栈中元素的下标index对应的temperatures[index]应该是一个单调递减数组。针对一个新的元素，我们首先检查栈，如果为空则直接把我们的下标push到栈中；如果我们的元素小于栈顶中存储的下标对应的元素，也push到栈中；如果我们的元素大于栈顶中存储的下标对应的元素，则说明栈顶中的下标找到了离它最近的，比他温度高的一天，栈顶pop出栈并把答案写入ans，我们遍历这个过程直到栈顶下标对应元素不再小于它，或者栈空了。

实现要点
#

如果我们的temperatures数组是从栈底到栈顶温度单调不增的话，我们就是一直在入栈，一次出栈的机会都没有，这时候我们的ans的初始化就颇为重要，我们让ans = [0] * len(temperatures)，保证了不出栈的元素的ans就是0。

易错点
#

注意在while判断中，还要思考到可能栈一直在pop导致栈空的情况，这时候元素下标直接入栈即可。

复杂度
#

时间复杂度 O(N) 空间复杂度 O(N)

84. 柱状图中最大的矩形 Largest Rectangle in Histogram
#

熟悉程度
#

B

题型
#

单调栈

识别信号
#

这题我们是可以想到要去遍历找“以一个元素作为高”的矩阵大小的最大值，这样的话我们就要找该元素左右的第一个小于该元素的元素位置，可以想到利用单调栈解决这种找下一个更小元素的问题。

核心思路
#

我们首先明确我们的思路就是去遍历每个元素，试图去找以该元素为高的情况下的矩阵大小，然后取最大值就是我们的答案，因此我们要用单调栈找该元素左右两边的第一个更小元素的位置，两个位置之差就是我们矩阵的底边。 那么我们怎么知道要用单调递增栈还是单调递减栈呢？一个核心思路就是看我们寻求的是找更大元素还是更小元素：

  • 找更小元素，比如这题，我们维护一个单调递增栈；新元素 < 栈顶下标对应元素 (不符合就入栈) —> 栈顶结算 —> pop
  • 找更大元素，比如上一题 739. 每日温度 ，我们维护一个单调递减栈；新元素 > 栈顶下标对应元素 (不符合就入栈) —> 栈顶结算 —> pop

而且其中我们知道的就是，单调栈中，遍历到的元素只是判断在哪个位置入栈，真正被处理的是出栈的元素，因为它找到了它需要的。

另外一点就是，我们只需要一次遍历就可以找到左右两边的最接近的更小元素！因为当某个元素被 pop 出栈的那一刻，它的左右最近更小元素同时都确定了。因为当栈顶元素出栈时，当前元素就是它右边最近的更小元素，而出栈后的栈顶就是它左边最近的更小元素。 因此可以通过一次遍历同时完成：维护单调递增栈、确定出栈元素左右最近的更小元素，并以出栈元素为高计算对应矩形面积。

实现要点
#

遍历数组，如果栈空（起始时）或者当前元素大于等于栈顶元素，我们将元素入栈；如果发现当前元素小于栈顶元素，我们就出栈栈顶元素，然后计算这个栈顶元素作为矩阵高对应的矩阵面积：

height = heights[stack[-1]]
stack.pop()
right = i
left = stack[-1]

ans = max(ans, height * (right - left - 1))

易错点
#

注意，为了代码的简洁性，我们可以给heights数组左右两头都加上一个0元素，开头加 0 是为了统一处理左边界，避免栈空；结尾加 0 是为了强制清栈（防止原数组就是一个单调递增数组，遍历过程中没有元素出栈）。

复杂度
#

时间复杂度 O(N) 空间复杂度 O(N)

做法二：

核心思路
#

做法一： 我们要找第K个最大的数，其实就可以去维护一个K大小的小根堆，遍历我们的数组去更新这个小根堆，小根堆堆顶的元素就是最后的答案。堆顶不是当前最大值，而是当前保留下来的 K 个最大值中最小的，所以最终正好是第 K 大。

实现要点
#

做法一： 我们去构造一个k大小的小根堆：如果小根堆还没有满，直接加入；如果小根堆满了，则去让新元素去和堆顶元素进行大小的对比。如果新元素更大，则pop堆顶元素，新元素push入堆。

易错点
#

做法一： 注意这题其实有点反直觉，就是明明是要找第K大的数，构造的是一个小根堆而不是一个大根堆。因为如果采用大根堆的做法，我们就是维护一个N大小的大根堆，然后连续弹出K次，每次弹出的复杂度都是O(logN)，算法的总时间复杂度是O(N + KlogN)，相当耗时。而使用小根堆就很自然，首先只需要一个K大小的小根堆，且最后堆顶元素就是我们要找的第K大的元素。

复杂度
#

做法一： 时间复杂度 O(NlogK)；每个元素入堆heappush耗时O(logK)，元素出堆heappop耗时O(logK) 空间复杂度 O(K)

295. 数据流的中位数 Find Median from Data Stream
#

熟悉程度
#

B

题型
#

大根堆 + 小根堆

识别信号
#

这里需要算中位数，我们可以想到维护两个大小相同或者大小只差一的堆，一个大根堆一个小根堆，然后计算堆顶元素即可。

核心思路
#

在这里我们去让相对更大的一半的数，去小根堆，另一半更小的数，去大根堆，最后计算中位数的时候有两种情况：

  1. 如果两个堆大小相同，则中位数是两个堆顶元素的平均数
  2. 如果大根堆的大小更大（我们希望原数组长度为奇数的时候，大根堆的大小 = 小根堆的大小 + 1），大根堆的堆顶元素就是我们的中位数。

在更新的时候，要注意：

  1. 我们先去看大根堆是否为空，如果空则元素直接push进大根堆，如果不为空则比较元素和大根堆堆顶元素，如果大于等于堆顶元素则push进堆。然后我们要去判断我们大根堆的大小有没有超出我们的限定范围，如果超出了则pop出堆顶元素，将它push进小根堆。平衡两边堆的大小。
  2. 如果一开始的判断不符合，说明这个元素应该push进小根堆。同样的，我们push进堆以后要去判断目前的堆的大小有没有超出范围。如果超出了就要平衡两边堆的大小。

实现要点
#

注意我们大根堆（存放较小部分的元素）在实现中应该是小根堆来存放一个负数的形式，要注意符号的转变。

易错点
#

注意在一开始的时候，大根堆小根堆都为空，所以要考虑到堆空的判断，我一开始的判断写了if(not self.larger_heap or num >= self.smaller_heap[0]):，这里就是没有注意到大根堆（存放较小部分的元素）有可能为空。应该改写为if(not self.larger_heap or num >= self.larger_heap[0]):

复杂度
#

时间复杂度 addNum:O(logN) 其中N为目前累计添加数的数量；findMedian:O(1) 空间复杂度 O(N)

堆
#

Python heapq 里常见操作复杂度可以直接记这几个：

  • heapq.heappush(heap, x)：O(log n)
  • heapq.heappop(heap)：O(log n)
  • heap[0] 查看堆顶：O(1)
  • heapq.heapify(arr) 建堆：O(n)
  • heapq.heappushpop(heap, x)：O(log n)
  • heapq.heapreplace(heap, x)：O(log n)

最重要的是记住这一句：建堆 O(n)，看堆顶 O(1)，插入和弹出 O(log n)。

912. 排序数组 Sort an Array
#

熟悉程度
#

B

题型
#

排序

识别信号
#

排序经典题，用来练习快速排序，归并排序，堆排序等排序算法！

核心思路
#

做法一： 记住快排的关键思路：pivot 放左边 —> 右边找小 —> 左边找大 —> 交换 —> 直到相遇 —> pivot 归位 —> 递归左右。

实现要点
#

做法一： 主要要理解partition(left, right)的作用： 把 pivot = nums[left] 放到它排序后应该在的位置，并保证左边都 <= pivot，右边都 >= pivot，最后返回 pivot 下标。

双指针移动顺序： 因为 pivot 取的是最左边，所以要先从右边 j 开始找 < pivot 的数，再从左边 i 找 > pivot 的数。否则容易把 pivot 位置覆盖乱。

循环结束时： i == j，这个位置就是 pivot 应该放的位置，所以最后交换：nums[left], nums[i] = nums[i], nums[left]。

递归范围： pivot 已经归位，不再参与递归：

quick_sort(left, pivot_index - 1)
quick_sort(pivot_index + 1, right)

具体代码：

class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        def partition(left, right):
            pivot = nums[left]
            i, j = left, right

            # 最终一定会结束在 i == j。
            while i < j:
                while i < j and nums[j] >= pivot:
                    j -= 1
                while i < j and nums[i] <= pivot:
                    i += 1
                nums[i], nums[j] = nums[j], nums[i]

            nums[left], nums[i] = nums[i], nums[left]
            return i

        def quick_sort(left, right):
            if left >= right:
                return

            pivot_index = partition(left, right)
            quick_sort(left, pivot_index - 1)
            quick_sort(pivot_index + 1, right)

        quick_sort(0, len(nums) - 1)
        return nums

易错点
#

做法一：

  1. while i < j 条件不能漏，否则指针可能越界。
  2. 内层移动也要带i < j的判断
  3. pivot 取左端时，要先移动右指针。
  4. 固定取 nums[left] 在有序数组上可能退化到 O(n^2)，如果要更稳，可以随机选 pivot。

复杂度
#

做法一： 时间复杂度 O(nlogn)，最坏情况下为O(n^2)（最坏情况为数组本身有序） 空间复杂度 O(logn)，最坏情况下O(n)
