CS336 Assignment 1 · 交互式学习笔记本

这一章不涉及任何具体模块的实现，而是打好后面所有章节都要用到的地基：张量、广播、einops、数值精度、可复现性，以及"如何对拍参考答案"这套贯穿全作业的验证范式。

学习目标
#

  1. 熟练读写张量的 shape / dtype / device，理解 ... 前导维度的约定。
  2. 掌握广播规则和 keepdim —— 这是后面 RMSNorm / attention 里最容易出 bug 的地方。
  3. 会用 einops.rearrange 做维度重排（作业推荐，比手写 permute/reshape 更不易错）。
  4. 理解浮点数值问题（溢出、低精度丢有效数字），从而明白为什么 softmax / cross-entropy / RMSNorm 要做特殊处理。
  5. 理解测试的对拍范式：你的实现 vs 参考答案 + assert_allclose 容差。

学术诚信：本笔记本用 PyTorch 内置函数当"教具/参考"来建立直觉，不包含任何要你在 adapters.py 里交付的实现。每章结尾的"✏️ 作业连接"只给思路，不给代码。

1. 张量：shape / dtype / device
#

整个作业里最常见的张量形状是 (batch, seq, d_model)。约定俗成：最后一维是特征维（d_model、d_k、vocab 等），前面的维度统称 ...（batch、序列、头数，可任意多个）。你的实现要对前导维度保持通用——这是 adapters.py 里 Float[Tensor, " ... d_out"] 这种类型注解在提醒你的事。

x = torch.randn(4, 12, 64)   # (batch=4, seq=12, d_model=64)
print("shape        :", tuple(x.shape))
print("dtype        :", x.dtype)
print("device       :", x.device)
print("ndim / numel :", x.ndim, "/", x.numel()) # ndim：张量的维度数量；x.numel()：表示张量里一共有多少个元素。
print("最后一维 (特征维) :", x.shape[-1])
print("前导维度  (...)   :", tuple(x.shape[:-1]))

shape        : (4, 12, 64)
dtype        : torch.float32
device       : cpu
ndim / numel : 3 / 3072
最后一维 (特征维) : 64
前导维度  (...)   : (4, 12)

2. 广播与 keepdim（重点！）
#

广播规则：从最后一维往前对齐，维度相等或其中一个为 1 时可广播。作业里两个高频场景：

  • 把一个 (d_model,) 的仿射参数乘到 (..., d_model) 上（RMSNorm 的 gain、Linear 的思路）。
  • 沿最后一维做归约（求均值/最大值），再广播回去——必须 keepdim=True，否则维度对不齐，会静默地广播到错误的轴。
x = torch.randn(4, 12, 64)
gain = torch.full((64,), 2.0)          # (d_model,)，创建一个长度为 64 的一维张量，里面每个元素都是 2.0。
y = x * gain                           # (64,) 广播到最后一维
print("x", tuple(x.shape), "* gain", tuple(gain.shape), "->", tuple(y.shape))

# 沿最后一维归约并保留维度 —— 才能广播回 x
ms_keep = (x ** 2).mean(dim=-1, keepdim=True) # 先对x里面每个元素平方（形状不变化），然后沿着最后一维求平均，同时因为keepdim=True，所以最后一维的维度不会消失，变成长度1
print("\nmean(dim=-1, keepdim=True):", tuple(ms_keep.shape),
      "| 能广播回 x?", (x / ms_keep).shape == x.shape) # 这里x / ms_keep就用到了广播

# 常见 bug：忘了 keepdim
ms_bad = (x ** 2).mean(dim=-1)
print("mean(dim=-1, keepdim=False):", tuple(ms_bad.shape),
      "| 若强行运算会对错维度或报错")

x (4, 12, 64) * gain (64,) -> (4, 12, 64)

mean(dim=-1, keepdim=True): (4, 12, 1) | 能广播回 x? True
mean(dim=-1, keepdim=False): (4, 12) | 若强行运算会对错维度或报错

🔬 小实验：下面故意制造一个"能广播但语义错"的例子。(12,) 会广播到 seq 维而不是你以为的 d_model 维——这类 bug 不报错，但结果全错。养成"运算前后都 print shape"的习惯。

x = torch.randn(4, 12, 64)
wrong = torch.ones(12)      # 想乘到 seq 维，但广播只会对齐最后一维
try:
    out = x * wrong
    print("意外没报错? shape =", tuple(out.shape))
except RuntimeError as e:
    print("广播失败(符合预期):", str(e).splitlines()[0])

# 想作用到 seq 维，必须显式把它 reshape 到对齐位置
right = torch.ones(12).reshape(1, 12, 1)
print("显式对齐后:", tuple((x * right).shape))

广播失败(符合预期): The size of tensor a (64) must match the size of tensor b (12) at non-singleton dimension 2
显式对齐后: (4, 12, 64)

3. einops：可读的维度重排
#

后面多头注意力要频繁地把 d_model 拆成 (head, d_head) 再拼回。手写 .view().permute() 很容易把轴的顺序搞反且难 debug。einops.rearrange 用带名字的模式字符串，一眼看懂、还会替你校验形状。这里只演示语法机制，不是注意力的实现。

q = torch.randn(4, 12, 64)              # (batch, seq, d_model)

# 把 d_model=64 拆成 head=4 * d_head=16，并把 head 提到 seq 前面
q_heads = rearrange(q, "b s (h d) -> b h s d", h=4) # 这里的h=4意思是把原来最后一维拆成h和d两个维度，其中h固定为 4。
print("拆头:", tuple(q.shape), "->", tuple(q_heads.shape))

# 逆操作拼回
q_back = rearrange(q_heads, "b h s d -> b s (h d)")
print("拼回:", tuple(q_back.shape), "| 和原始逐元素相等?", torch.allclose(q, q_back))

# reduce 也能带名字做归约（等价于 mean(dim=...)）
# reduce 是用来沿某些维度做聚合运算，所以通常会减少元素数量。
rms_like = reduce(q ** 2, "b s d -> b s 1", "mean")
print("沿 d 归约:", tuple(rms_like.shape))

拆头: (4, 12, 64) -> (4, 4, 12, 16)
拼回: (4, 12, 64) | 和原始逐元素相等? True
沿 d 归约: (4, 12, 1)

4. 浮点数值：为什么后面要"小心"
#

softmax、cross-entropy、RMSNorm 的实现难点几乎都在数值稳定，而不是公式本身。先亲眼看看浮点会怎么"爆"和"丢精度"，你就理解了那些测试里 x + 100、1000 * inputs 的用意。

# (1) 大数取 exp 溢出为 inf —— 朴素 softmax 会在这里挂
big = torch.tensor([1000.0])
print("exp(1000.) float32 =", torch.exp(big).item(), " <- inf")

# (2) float16 动态范围很窄，上限约 65504
half = torch.tensor([65600.0], dtype=torch.float16)
print("65600 存成 float16 =", half.item(), " <- inf")

# (3) 低精度丢有效数字：在大数上反复加小数，fp16 会把小增量整个丢掉
acc16 = torch.tensor(1000.0, dtype=torch.float16)
acc32 = torch.tensor(1000.0, dtype=torch.float32)
step16 = torch.tensor(0.1, dtype=torch.float16)
step32 = torch.tensor(0.1, dtype=torch.float32)
for _ in range(100):
    acc16 = acc16 + step16
    acc32 = acc32 + step32
print("\n1000 上加 100 次 0.1:")
print("  float16 =", acc16.item(), " <- 卡在 1000，小增量低于该量级的分辨率被丢光")
print("  float32 =", round(acc32.item(), 4), " <- 约等于期望的 1010")
print("\n结论：指数/归约/累加类运算先 upcast 到 float32 再算，能显著更稳更准。")

exp(1000.) float32 = inf  <- inf
65600 存成 float16 = inf  <- inf

1000 上加 100 次 0.1:
  float16 = 1000.0  <- 卡在 1000，小增量低于该量级的分辨率被丢光
  float32 = 1009.9976  <- 约等于期望的 1010

结论：指数/归约/累加类运算先 upcast 到 float32 再算，能显著更稳更准。

5. 可复现性：manual_seed
#

tests/conftest.py 里每个输入 fixture 都先调用 torch.manual_seed(k) 再生成随机张量，所以测试完全可复现——同样的 seed 永远给同样的数。这意味着测试挂了你可以精确重跑复现，不必怀疑是随机波动。

torch.manual_seed(4); a = torch.randn(2, 3)
torch.manual_seed(4); b = torch.randn(2, 3)
torch.manual_seed(5); c = torch.randn(2, 3)
print("同 seed 两次 -> 相等 :", torch.equal(a, b))
print("换 seed     -> 不同 :", not torch.equal(a, c))
print("\na =\n", a)

同 seed 两次 -> 相等 : True
换 seed     -> 不同 : True

a =
 tensor([[-1.6053,  0.2325,  2.2399],
        [ 0.8473,  1.2006, -0.4016]])

6. 对拍范式：本作业验证的核心
#

每个 test_*.py 做的事本质上是：

你的输出 = run_xxx(固定输入, 参考权重)
np.testing.assert_allclose(你的输出, 参考答案, rtol, atol)

参考答案存在 tests/_snapshots/*.npz 里（test_linear ↔ _snapshots/test_linear.npz）。atol/rtol 是容差：差一点点（在容差边缘）多半是 dtype/eps 问题，差很多是逻辑错。

下面用一个已知正确的小例子演示这套流程本身——把"手写三重循环矩阵乘"和"torch 的 @“对拍。这只是教你验证方法，不是任何作业解答。

torch.manual_seed(0)
A = torch.randn(2, 3)
B = torch.randn(3, 4)
reference = A @ B                      # 当作"参考答案"

# "我的实现"：最朴素的三重循环（仅演示对拍）
mine = torch.zeros(2, 4)
for i in range(2):
    for j in range(4):
        for k in range(3):
            mine[i, j] += A[i, k] * B[k, j]

max_abs_err = (mine - reference).abs().max().item()
np.testing.assert_allclose(mine.numpy(), reference.numpy(), atol=1e-5) # 去判断这两个数的偏差是不是小于atol
print("assert_allclose 通过 (atol=1e-5)")
print("最大绝对误差:", max_abs_err)
print("\n这正是 numpy_snapshot.assert_match 在做的事，只不过参考答案来自 .npz 快照。")

assert_allclose 通过 (atol=1e-5)
最大绝对误差: 2.384185791015625e-07

这正是 numpy_snapshot.assert_match 在做的事，只不过参考答案来自 .npz 快照。

🔬 实用技巧：想在写实现前就知道某个测试期望的输出形状，可以直接读它的快照。下面看 test_linear 的参考答案长什么样——注意它的最后一维是 d_ff=128（因为该测试用 w1 把 64 投影到 128）。

你可以把.npz文件理解成一个“装了多个 NumPy 数组的压缩包”。np.load(snap) 读出来后，里面有很多数组，每个数组都有一个名字。其中dict的k就是数组的名字，v就是具体对应的numpy数字。

import pathlib
snap = pathlib.Path("tests/_snapshots/test_linear.npz")
if not snap.exists():
    snap = pathlib.Path("../tests/_snapshots/test_linear.npz")

d = dict(np.load(snap))
for k, v in d.items():
    print(f"key={k!r:10} shape={v.shape} dtype={v.dtype} mean={v.mean():.4f}")
print("\n=> 你的 run_linear 输出应当匹配这个 shape 和数值(在容差内)。")

key='array'    shape=(4, 12, 128) dtype=float32 mean=-0.0072

=> 你的 run_linear 输出应当匹配这个 shape 和数值(在容差内)。

小结
#

  • 张量约定：最后一维是特征维，前导 ... 要通用处理。
  • keepdim=True 是归约后广播的关键；运算前后 print shape 能抓到大多数 bug。
  • einops.rearrange 让拆头/拼头这类操作可读且自校验。
  • 指数与归约类运算先 upcast 到 float32；这解释了后面 softmax / cross-entropy / RMSNorm 的稳定性要求。
  • 测试 = 固定输入 → run_xxx → 和 .npz 快照对拍；容差告诉你误差是"数值级"还是"逻辑级”。

✏️ 作业连接（只给思路，不给实现）
#

这一章没有对应的 run_xxx，但它给你的工具会贯穿全程：

  • 写任何 run_xxx 时，先在纸上/心里推出输入输出 shape，再动手；实现里临时加 assert x.shape == (...)，过测试后删掉。
  • 遇到"差一点点"没过：先怀疑 dtype / eps / keepdim。
  • 遇到"差很多"：用 (2,3) 级别的玩具输入手算对比，别在 (4,12,64) 上肉眼 debug。
  • 想知道期望输出：读对应的 .npz 快照的 shape。
