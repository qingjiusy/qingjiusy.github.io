注意力是 Transformer 的心脏。这一章帮你把 Q/K/V 的角色、为什么要除以 √d_k、mask 怎样在 softmax 之前生效 这三件事想透，最后给出一份"带步骤注释的骨架"让你自己填 ScaledDotProductAttention。

学习目标
#

  1. 说清 Q / K / V 各自扮演什么角色（query 去找、key 被匹配、value 被聚合）。
  2. 用一个方差实验亲眼看到：点积方差随 d_k 线性增长，除以 √d_k 后方差≈1，从而理解不缩放为什么会让 softmax 饱和、梯度消失。
  3. 理解 bool mask 的约定（True 保留 / False 屏蔽），以及为什么要在 softmax 之前把屏蔽位置置为极负值。
  4. 用因果 mask 的热图看到"每个 query 只能看被允许的 key"，被屏蔽位置权重≈0。
  5. 拿到 ScaledDotProductAttention 的引导骨架，知道自己该在 cs336_basics/ 里写什么，以及必须支持任意前导 batch 维（4D 测试）。

1. Q / K / V 的角色
#

注意力做的事，一句话：每个 query 去和所有 key 比对相似度，再据此把对应的 value 加权聚合起来。

  • Query（查询）：当前这个位置"想找什么信息"。
  • Key（键）：每个位置"用什么标签来被检索"。
  • Value（值）：每个位置"真正要贡献出去的内容"。

相似度用点积衡量：scores = Q · Kᵀ，scores[i, j] 就是 query_i 和 key_j 的点积——越大代表越该关注。下面用一个 2 维玩具例子建立直觉。

# 玩具：4 个 token，用一个 2D 方向向量表示"语义"。
# token 0/1 指向"右"，token 2/3 指向"上" —— 同向的理应互相匹配。
Q = torch.tensor([[1.0, 0.0],
                  [0.9, 0.1],
                  [0.0, 1.0],
                  [0.1, 0.9]])
K = Q.clone()          # 自注意力：query 与 key 来自同一批 token
scores = Q @ K.T       # (4, 4)：第 i 行第 j 列 = query_i · key_j
print("原始打分矩阵 scores = Q·Kᵀ :")
print(scores)
print("\n观察对角块：{0,1} 互相得分高、{2,3} 互相得分高，跨组得分低。")
print("点积越大 = 方向越接近 = 越应该被关注 —— 这就是注意力的'匹配'。")

tensor([[1.0000, 0.9000, 0.0000, 0.1000],

        [0.0000, 0.1000, 1.0000, 0.9000],
        [0.1000, 0.1800, 0.9000, 0.8200]])

观察对角块：{0,1} 互相得分高、{2,3} 互相得分高，跨组得分低。
点积越大 = 方向越接近 = 越应该被关注 —— 这就是注意力的'匹配'。

2. 为什么要除以 √d_k（方差实验）
#

scores 会直接喂给 softmax。问题来了：当特征维度 d_k 变大时，点积的数值尺度会随之变大。

直觉：q · k = Σ_{t=1}^{d_k} q_t k_t 是 d_k 个独立项之和。若各分量 ~ N(0,1) 且相互独立，则每一项方差≈1，求和后方差≈d_k——方差随 d_k 线性增长。下面用采样实验验证。

$$\operatorname{Var}(aX)=a^2\operatorname{Var}(X)$$$$\operatorname{Var}(z)=\operatorname{Var}\left(\frac{q\cdot k}{\sqrt{d_k}}\right)=\frac{1}{d_k}\operatorname{Var}(q\cdot k)\approx\frac{1}{d_k}\cdot d_k=1$$

。 因此我们应该除d_k的根号，让送入 softmax 的 logits 不会随着 head dimension 增大而越来越大，从而避免 softmax 过度饱和。

# 方差实验：随机 q, k ~ N(0,1)，统计点积 q·k 的方差随 d_k 的变化
torch.manual_seed(0)
dks = [1, 2, 4, 8, 16, 32, 64, 128, 256]
N = 20000                      # 每个 d_k 采样这么多对向量
var_raw, var_scaled = [], []
for d in dks:
    q = torch.randn(N, d)
    k = torch.randn(N, d)
    dot = (q * k).sum(-1)                      # N 个点积
    var_raw.append(dot.var().item())          # 未缩放
    var_scaled.append((dot / math.sqrt(d)).var().item())  # 除以 sqrt(d_k)

fig, ax = plt.subplots(1, 2, figsize=(10, 4))
ax[0].plot(dks, var_raw, "o-", label="measured")
ax[0].plot(dks, dks, "k--", alpha=.5, label="y = d_k")
ax[0].set_title("unscaled: Var(q . k) grows ~ d_k")
ax[0].set_xlabel("d_k"); ax[0].set_ylabel("variance"); ax[0].legend()
ax[1].plot(dks, var_scaled, "o-", label="measured")
ax[1].axhline(1.0, c="k", ls="--", alpha=.5, label="y = 1")
ax[1].set_title("after / sqrt(d_k): variance ~ 1")
ax[1].set_xlabel("d_k"); ax[1].set_ylabel("variance"); ax[1].legend()
for a_ in ax:
    a_.grid(alpha=.3)
plt.tight_layout(); plt.show()
print("未缩放：方差≈ d_k（左图贴着虚线 y=d_k）。")
print("除以 √d_k 后：方差≈ 1，与 d_k 无关（右图贴着 y=1）。")


未缩放：方差≈ d_k（左图贴着虚线 y=d_k）。
除以 √d_k 后：方差≈ 1，与 d_k 无关（右图贴着 y=1）。

大尺度的 scores 为什么有害：softmax 饱和
#

softmax 对输入尺度很敏感。同一组 logits，整体放大若干倍后，输出会迅速变"尖"——几乎所有概率压到最大的那一个位置（趋近 one-hot）。一旦饱和，其余位置的梯度≈0，反向传播几乎学不到东西，训练变得不稳定。

下面拿 F.softmax（黑盒）看这个饱和现象。

# 同一组 logits，逐步放大整体尺度，观察 softmax 如何饱和到 one-hot
logits = torch.tensor([2.0, 1.0, 0.0, -1.0])
print("logits =", logits.numpy())
for scale in [1, 3, 10]:
    w = F.softmax(logits * scale, dim=-1)
    print(f"scale={scale:2d}  softmax={np.round(w.numpy(), 3)}   max_prob={w.max():.3f}")
print("\n尺度放大 -> 分布迅速尖化(接近 one-hot) -> 非最大位置梯度≈0。")
print("这正是'不除以 √d_k、让 scores 随 d_k 变大'会导致梯度消失/训练不稳的机制。")

logits = [ 2.  1.  0. -1.]
scale= 1  softmax=[0.644 0.237 0.087 0.032]   max_prob=0.644
scale= 3  softmax=[0.95  0.047 0.002 0.   ]   max_prob=0.950
scale=10  softmax=[1. 0. 0. 0.]   max_prob=1.000

尺度放大 -> 分布迅速尖化(接近 one-hot) -> 非最大位置梯度≈0。
这正是'不除以 √d_k、让 scores 随 d_k 变大'会导致梯度消失/训练不稳的机制。

3. Mask：因果 mask 与"softmax 之前置极负值"
#

有时我们不希望某些 query 看到某些 key。最典型的是因果（causal）mask：语言模型里位置 i 的 query 只能看 j ≤ i 的 key，不能偷看未来。

adapters 里的 mask 是 bool 张量，形状 (... queries keys)，约定：

  • True = 保留（这个 key 可以被这个 query 看到）
  • False = 屏蔽（不允许看到）

关键在怎么屏蔽：要在 softmax 之前，把 False 的位置加上一个极大的负数。这样 exp(极负值) ≈ 0，softmax 后该位置权重≈0，而且这样的话被屏蔽位置完全不参与softmax中的归一化（只有可以被看到的位置的概率和为1）。先看因果 mask 长什么样。

# 因果 mask：query i 只能看 key j <= i（下三角为 True）
seq = 8
causal = torch.tril(torch.ones(seq, seq, dtype=torch.bool))   # True = 允许
plt.figure(figsize=(4.4, 4))
plt.imshow(causal.numpy(), cmap="Greys", origin="upper")
plt.title("causal mask  (True=keep, lower-triangular)")
plt.xlabel("key position j"); plt.ylabel("query position i")
plt.colorbar(ticks=[0, 1])
plt.tight_layout(); plt.show()
print("黑=True（保留），白=False（屏蔽）。上三角（未来）被屏蔽。")
print("实现时：在 softmax *之前* 给 False 处加一个极负值 -> exp 后≈0 -> 权重≈0。")


黑=True（保留），白=False（屏蔽）。上三角（未来）被屏蔽。
实现时：在 softmax *之前* 给 False 处加一个极负值 -> exp 后≈0 -> 权重≈0。

用内置件观察注意力权重热图
#

我们想直接"看到"注意力权重矩阵，但 F.scaled_dot_product_attention 只返回聚合后的输出、不返回权重。这里有个干净的黑盒小技巧：

令 V = 单位矩阵 I（形状 keys × keys），那么输出的第 i 行恰好就是 query_i 对各 key 的权重分布！

因为"对 value 加权求和"里，如果每个 value 就是一个 one-hot 基向量，加权和自然还原出权重本身。这样我们把 SDPA 当纯黑盒用，就能画权重热图、对比加不加因果 mask。

# V = 单位矩阵 -> F.scaled_dot_product_attention 的输出 = 注意力权重矩阵
torch.manual_seed(7)
seq, d = 8, 16
Qh = torch.randn(seq, d)
Kh = torch.randn(seq, d)
V_identity = torch.eye(seq)                 # (keys, keys)

w_full   = F.scaled_dot_product_attention(Qh, Kh, V_identity)                  # 无 mask
w_causal = F.scaled_dot_product_attention(Qh, Kh, V_identity, is_causal=True)  # 因果 mask

fig, ax = plt.subplots(1, 2, figsize=(10, 4.2))
for a_, w, t in [(ax[0], w_full,   "no mask: attends to all keys"),
                 (ax[1], w_causal, "causal: future keys get ~0 weight")]:
    im = a_.imshow(w.detach().numpy(), cmap="viridis", vmin=0, vmax=1)
    a_.set_title(t); a_.set_xlabel("key j"); a_.set_ylabel("query i")
    fig.colorbar(im, ax=a_, fraction=0.046)
plt.tight_layout(); plt.show()

print("每行权重和为 1（softmax 沿 keys 维归一化）:", np.round(w_causal.sum(-1).detach().numpy(), 3))
print("右图上三角(未来)≈0。例如 query0 看 key7 的权重 =", float(w_causal[0, 7]))
print("对比: 无 mask 时 query0 看 key7 的权重 =", round(float(w_full[0, 7]), 4))


每行权重和为 1（softmax 沿 keys 维归一化）: [1. 1. 1. 1. 1. 1. 1. 1.]
右图上三角(未来)≈0。例如 query0 看 key7 的权重 = 0.0

需要区分清楚的一些 Attention 中的名词
#

Attention 的整体计算流程为：

$$ X \rightarrow Q,K,V \rightarrow QK^\top \rightarrow \frac{QK^\top}{\sqrt{d_k}} \rightarrow \text{Mask} \rightarrow \text{Softmax} \rightarrow AV $$

下面介绍每一步对应的名词。

1. Query、Key、Value（Q、K、V）
#

输入序列表示为：

$$ X\in\mathbb{R}^{n\times d_{\text{model}}} $$

经过三个不同的线性变换得到：

$$ Q=XW_Q $$$$ K=XW_K $$$$ V=XW_V $$

它们可以简单理解为：

  • Query（查询）：我想寻找什么信息。
  • Key（键）：我具有什么特征，可以被别人匹配。
  • Value（值）：我真正能够提供什么信息。

对于第 $i$ 个 Query 和第 $j$ 个 Key：

$$ q_i $$

表示第 $i$ 个 Token 希望寻找的信息。

$$ k_j $$

表示第 $j$ 个 Token 用于被匹配的特征。

$$ v_j $$

表示第 $j$ 个 Token 最终提供的信息。

2. 注意力分数（Attention Score）
#

首先计算 Query 与 Key 的点积：

$$ S=QK^\top $$

其中：

$$ s_{ij}=q_i\cdot k_j $$

表示 第 $i$ 个 Query 与第 $j$ 个 Key 的匹配程度。

此时得到的称为 注意力分数（Attention Score），也常被称为：

  • Raw Attention Score
  • Similarity Score

注意：

  • 可以为负数；
  • 不在 $0\sim1$ 之间；
  • 每一行的和不等于 1；
  • 还没有经过 Softmax，因此不是注意力权重。

3. 缩放注意力分数（Scaled Attention Score）
#

为了防止维度 $d_k$ 增大导致点积越来越大，需要除以：

$$ \sqrt{d_k} $$

得到：

$$ \frac{QK^\top}{\sqrt{d_k}} $$

对应单个元素：

$$ \frac{q_i\cdot k_j}{\sqrt{d_k}} $$

这一步得到的通常称为：

  • Scaled Attention Score
  • Attention Logits（很多论文也这样称呼）

它仍然属于 Softmax 之前的分数。

4. Mask 后的 Attention Logits
#

对于因果 Attention，需要将未来位置屏蔽：

$$ L= \frac{QK^\top}{\sqrt{d_k}} + M $$

其中：

  • 可见位置加上 $0$；
  • 被屏蔽位置加上 $-\infty$（实际实现中通常使用一个极大的负数）。

Mask 之后得到的仍然属于 Attention Logits，只是已经包含了 Mask 信息。

5. 注意力权重（Attention Weight）
#

随后按行进行 Softmax：

$$ A
#

\operatorname{softmax}(L) $$

即：

$$ a_{ij}
#

\frac{\exp(L_{ij})} {\sum_t\exp(L_{it})} $$

其中：

$$ a_{ij} $$

表示 第 $i$ 个 Query 最终从第 $j$ 个 Value 获取多少比例的信息。

注意力权重具有以下特点：

  • 每个元素都位于 $[0,1]$；
  • 每一行所有权重之和等于 $1$；
  • 如果使用了 Mask，则只有允许看到的位置的权重之和等于 $1$。

矩阵：

$$ A $$

也常被称为：

  • Attention Weight Matrix
  • Attention Probability Matrix
  • Attention Map
  • Attention Pattern

6. 注意力输出（Attention Output）
#

最后使用注意力权重对所有 Value 做加权求和：

$$ O=AV $$

其中：

$$ o_i=\sum_j a_{ij}v_j $$

表示：

第 $i$ 个 Token 根据注意力权重，从所有可见 Token 的 Value 中汇总得到的信息。

它通常被称为：

  • Attention Output
  • Context Vector（上下文向量）

需要注意：

Attention Output 并不是 Attention Weight。

Attention Weight 决定看谁、看多少；

Attention Output 则是真正取回来的信息。

4. ✏️ 你的任务：ScaledDotProductAttention 引导骨架
#

下面是给你填的骨架（... 处留白，定义可运行但不做实际计算，也不实例化调用）。

对照 tests/adapters.py 里 run_scaled_dot_product_attention 的签名：

  • Q: (... queries d_k)，K: (... keys d_k)，V: (... keys d_v)
  • mask: 可选 bool，(... queries keys)，True 保留 / False 屏蔽
  • 返回：(... queries d_v)

必须支持任意前导 batch 维——test_4d_scaled_dot_product_attention 会传 (batch, head, seq, d)。想清楚每一步"哪两维在收缩、前导维怎么广播"，用一个 (2,3)×(2,3) 的小例子在纸上摆一摆再写。softmax 直接复用你在 run_softmax 里已经实现的那个（注意它的数值稳定处理）。

from cs336_basics.softmax import softmax

def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q: (..., queries, d_k)   K: (..., keys, d_k)   V: (..., keys, d_v)
    # mask (可选): bool (..., queries, keys)，True=保留 / False=屏蔽
    # 要求：支持任意前导 batch 维（见 4D 测试），全程用广播、不要写死维数

    # step 1: 打分 scores = Q · Kᵀ。想清楚最后两维怎么乘：
    #   (queries, d_k) 与 (keys, d_k) 要收缩掉 d_k，得到 (queries, keys)。
    #   -> K 的最后两维需要转置；前导 batch 维保持广播。
    K_t = einops.rearrange(K, "... seq d -> ... d seq")
    scores = Q @ K_t # 因为 PyTorch 的 @ 对高维张量有固定规则：对最后两个维度做矩阵乘法，前面的维度当作 batch 维进行广播。

    # step 2: 缩放。除以 √d_k，其中 d_k = Q 最后一维的大小。（回忆第 2 节的方差实验：这一步让 softmax 输入不随 d_k 爆炸。）
    d_k = Q.shape[-1]
    scaled_scores = scores / (d_k ** 0.5)

    # step 3: 应用 mask（若提供）。在 softmax *之前*，把 mask 为 False 的位置加上一个极大的负数，使其 exp 后≈0。想清楚用什么值、怎么按 scores 广播。
    # 使用api：scores.masked_fill(condition, value)。含义是：在 condition == True 的位置，把 scores 替换成 value。
    if mask is not None:
        logits = scaled_scores.masked_fill(~mask, float("-inf")) # ~ 是取反操作

    # step 4: 沿 keys 维做 softmax，得到注意力权重。
    #   （复用你已实现的 softmax，并想清楚是最后哪一维归一化。）
    weights = softmax(logits, dim=-1)

    # step 5: 用权重对 V 加权求和，得到 (..., queries, d_v)。
    #   再想一次：这里哪两维在收缩？
    return weights @ V

🔬 拓展实验（自己动手，加深理解）
#

  1. 广播自检：在写实现前，先只做 step 1，给它喂 (12,64)×(16,64)、(4,12,64)×(4,16,64)、(4,2,12,64)×(4,2,16,64) 三种形状，确认 scores 分别是 (12,16)、(4,12,16)、(4,2,12,16)。前导维错了通常是转置或广播写死了维数。
  2. mask 屏蔽值：“极负值"用 -1e9 和用 float('-inf') 有什么区别？想想若某一行整行都被屏蔽（全 False）会发生什么（softmax 会得到什么？会不会出 NaN？）。这在因果 mask 里通常不会发生，但值得心里有数。
  3. 缩放消融：把第 2 节的 V=I 技巧用起来，对比"有缩放 vs 无缩放"下、当 d_k 很大时注意力权重是不是更容易塌成 one-hot。这直观复现了"为什么要 √d_k”。
  4. softmax 沿哪一维：故意把 softmax 的 dim 写错（比如沿 queries 维），跑 test_scaled_dot_product_attention，看报的是形状错误还是数值错误——理解错误信息能帮你快速定位这类 bug。

答案
#

  1. 略
  2. -1e9 和 float("-inf") 在一行中至少存在一个未屏蔽位置时，效果通常非常接近。但是如果整行都被屏蔽时，使用 float("-inf")的整行变为[-∞, -∞, -∞]，稳定版softmax减去最大值：-∞ - -∞ = NaN。经过softmax以后会得到[NaN, NaN, NaN]。如果使用使用 -1e9，则通过稳定版softmax减去最大值以后，我们会得到一个均匀分布[1/3, 1/3, 1/3]
  3. 略
  4. **Softmax 必须沿着 Key（最后一维）做，而不是沿着 Query 那一维。**因为从原理上讲，对于每一个 Query，我们希望把它对所有 Key 的匹配分数归一化为一个概率分布。也就是去让每个 Query 对所有 Key 的注意力权重之和等于 1。如果softmax的dim写错，不会报形状错误，因为softmax操作本身就不会改变矩阵形状，但是这不符合我们的attention定义，attention weights全部算错了，会导致数值错误。

小结
#

  • 注意力 = query 找 key（点积打分）→ softmax 归一化 → 聚合 value。scores[i,j] = q_i · k_j 衡量相似度。
  • 除以 √d_k 的理由：点积方差随 d_k 线性增长，不缩放会让 softmax 饱和、梯度消失（第 2 节方差实验亲眼可见）。
  • mask 在 softmax 之前生效：bool mask True 保留、False 屏蔽；给 False 处加极负值，使 exp≈0、权重≈0，且不参与归一化。
  • 实现的关键是想清楚每一步哪两维收缩、前导 batch 维怎么广播——别把维数写死，才能同时过 3D 和 4D 测试。
