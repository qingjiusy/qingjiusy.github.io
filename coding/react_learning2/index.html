开始学习redux部分

什么是Redux?
#

Redux是React最常用的集中状态管理工具，类似于Vue中的Pinia（Vuex），可以独立于框架运行

作用：通过集中管理的方式管理应用的状态

为了职责清晰，数据流向明确，Redux把整个数据修改的流程分成了三个核心概念，分别是：state、action和reducer

  1. state-一个对象存放着我们管理的数据状态
  2. action-一个对象用来描述你想怎么改数据
  3. reducer-一个函数更具action的描述生成一个新的state

Redux 核心概念
#

Store（存储）
#

  • Redux 的 中央存储，存放整个应用的状态（state）。
  • 通过 createStore() 创建。

Action（动作）
#

  • 一个普通的 JavaScript 对象，描述 需要进行的状态变更。
  • 必须包含 type 字段，表示变更的类型，可以包含 payload 传递额外数据。

Reducer（状态更新器）
#

  • 纯函数，根据 action 的 type 计算新的 state，并返回 新的状态（不会修改原来的状态）。
  • 由 Redux 自动调用，决定如何更新 state。

Dispatch（分发）
#

  • 触发 action 的方法，通知 reducer 进行状态更新。
  • 使用 store.dispatch(action) 来提交 action。

Subscribe（订阅）
#

  • 监听 store 状态的变化，数据更新时触发回调。
  • 使用 store.subscribe(listener) 来订阅状态变化。

getState（获取状态）
#

  • 通过 store.getState() 获取当前 store 的最新 state。

提交action传参
#

在reducers的同步修改方法中添加action对象参数，在调用actionCreater的时候传递参数，参数会被传递到action对象payload属性上

比如在store中：

addToNum (state, action) {
      state.count = action.payload
    }

redux与react的异步状态操作
#

主要思路和上面还是基本一致的：

  1. 创建store的写法保持不变，配置好同步修改状态的方法
  2. 单独封装一个函数，在函数内部return一个新函数，在新函数中:
    1. 封装异步请求获取数据，比如：
    const response = await fetch("https://api.example.com/data")
const data = await response.json()
    1. 调用同步actionCreater传入异步数据生成一个action对象，并使用dispatch提交
  3. 组件中dispatch的写法保持不变

实现添加购物车
#

使用RTK管理新状态cartList，思路主要是：如果添加过该商品，那么state中count就自加1，否则就传入1。而具体在前端页面中，用对应的dispatch方法来引起对应的变化。其中reducers中的对应action，也就是addCart的实现如下，可以看到就是上面的逻辑：

addCart (state, action) {
            //要判断是否添加过？以action.payload.id去cartList匹配查找
            const item = state.cartList.find(item => item.id === action.payload.id)
            if(item){
                item.count ++
            } else {
                //保证了count字段的存在
                state.cartList.push({...action.payload, count:1})
            }
        }
