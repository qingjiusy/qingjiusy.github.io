读懂 over (...)
#

下面使用 MySQL 8.0 语法，相关规则核对于 2026-10-23。分析一下窗口函数。

先准备一张小表
#

假设有一张销售记录表 sales，每行代表一笔销售：

id employee sale_date amount
1 A 2026-10-01 100
2 A 2026-10-02 200
3 A 2026-10-03 150
4 B 2026-10-01 80
5 B 2026-10-02 120

想自己运行，可以先执行下面的建表和插入语句：

create temporary table sales (
    id int primary key,
    employee varchar(10),
    sale_date date,
    amount int
);

insert into sales (id, employee, sale_date, amount) values
(1, 'A', '2026-10-01', 100),
(2, 'A', '2026-10-02', 200),
(3, 'A', '2026-10-03', 150),
(4, 'B', '2026-10-01', 80),
(5, 'B', '2026-10-02', 120);

这里用临时表练习，后续查询在同一个数据库连接中执行即可。

over：为当前行规定计算规则
#

先看最简单的写法：

select
    id, employee, amount,
    sum(amount) over () as total_amount
from sales
order by id;
id employee amount total_amount
1 A 100 650
2 A 200 650
3 A 150 650
4 B 80 650
5 B 120 650

sum(amount) 负责说明“做什么计算”，over (...) 负责规定窗口。这里括号里什么都没写，所以把所有记录放在一起求和，每行旁边都得到一个 650。

窗口函数本身不会把这些明细行合并掉，而是为每行计算一个结果。 可以把“当前行”理解成：现在正在给哪一行填写结果。

这里的“所有记录”指当前查询交给窗口函数处理的行。如果查询有 where，会先过滤，再做窗口计算，并不一定包含原表的全部数据。窗口函数与普通聚合的区别可参考 MySQL 官方概念说明。

partition by：和谁一起算？
#

如果题目变成“保留每笔销售，同时显示这名员工的销售总额”，就需要让 A 和 A 一起算，B 和 B 一起算。

select
    id, employee, amount,
    sum(amount) over (
        partition by employee
    ) as employee_total
from sales
order by id;
id employee amount employee_total
1 A 100 450
2 A 200 450
3 A 150 450
4 B 80 200
5 B 120 200

partition by employee 的意思是：按员工划分分区，各个分区独立计算。

比如当前行是 id = 2，它属于 A 的分区，所以总额是 100 + 200 + 150 = 450。到了 B 的记录，就只计算 B 的金额。

它和 group by employee 都有“分组”的意思，但结果的粒度不同：

  • 用 group by employee 求和，每名员工得到一行。
  • 用 sum(amount) over (partition by employee)，每笔销售仍然保留，只是在旁边增加员工总额。

所以，看到题目要求“每个用户”“每个部门”“每种商品”分别计算，同时还需要保留明细时，就可以想想 partition by。

order by：按什么顺序算？
#

接下来把问题改成：对每名员工，按销售日期统计截至当前这笔的累计金额。

“总额”不关心先后，但“累计”需要先确定顺序。这里把完整写法先放出来，窗口范围下一小节再拆：

select
    id, employee, sale_date, amount,
    sum(amount) over (
        partition by employee
        order by sale_date, id
        rows between unbounded preceding and current row
    ) as running_total
from sales
order by employee, sale_date, id;
id employee sale_date amount running_total
1 A 2026-10-01 100 100
2 A 2026-10-02 200 300
3 A 2026-10-03 150 450
4 B 2026-10-01 80 80
5 B 2026-10-02 120 200

order by sale_date, id 表示在各自的分区内，先按日期升序排列；如果日期相同，再按唯一的 id 排列，让逐笔累计的顺序明确。

对 A 来说，累计过程就是：

第一笔：100             = 100
第二笔：100 + 200       = 300
第三笔：100 + 200 + 150 = 450

到 B 的分区时，累计会重新开始。

这里出现了两个 order by，它们各有用途：over 里面的决定窗口计算的顺序，查询最外层的决定结果展示的顺序。 想保证最后输出的行有序，仍然需要外层 order by，不能只依赖窗口里的排序。官方语法说明

窗口范围：这一次算哪些行？
#

分区和顺序确定后，还要回答：给当前行计算结果时，是使用整个分区，还是只取其中一段？

这段范围叫作 frame（窗口帧）。上面的累计例子中：

rows between unbounded preceding and current row

可以拆成：

写法 含义
rows 按排序后的行位置确定范围
between ... and ... 指定起点和终点，包含两端
unbounded preceding 当前分区的第一行
current row 当前行

连起来就是：从当前分区第一行，一直算到当前行。

窗口范围会随当前行的位置变化，但不会越过分区边界。这正好对应“每名员工各自累计”。

如果要计算“当前这笔加上前一笔的金额”，只需要把范围换成：

select
    id, employee, amount,
    sum(amount) over (
        partition by employee
        order by sale_date, id
        rows between 1 preceding and current row
    ) as last_two_total
from sales
order by employee, sale_date, id;
id employee amount 参与计算的金额 last_two_total
1 A 100 100 100
2 A 200 100 + 200 300
3 A 150 200 + 150 350
4 B 80 80 80
5 B 120 80 + 120 200

表里的“参与计算的金额”是为了理解额外加上的说明列，并不是 SQL 输出列。

1 preceding 就是前一行；分区第一行没有前一行，就只计算当前行。尤其注意 B 的第一笔不会把 A 的最后一笔带进来。

常见范围先记住下面三种就够用了：

-- 从分区开头累计到当前行
rows between unbounded preceding and current row

-- 最近三行，包括当前行；不足三行时使用已有行
rows between 2 preceding and current row

-- 整个分区
rows between unbounded preceding and unbounded following

最近三行不一定是最近三天。 一天可能有多条记录，也可能有日期没有记录，rows 只数行的位置。

这里用 sum() 理解窗口帧即可。MySQL 中的排名函数以及 lag()、lead() 不受这个 frame 子句限制，不能以为所有窗口函数都会按它截取计算范围。官方窗口帧说明

不写窗口范围，会发生什么？
#

对这里的 sum() 来说，默认范围和窗口里有没有 order by 有关：

  • 没有 order by，也没指定范围：使用整个分区，所以前面的员工总额每行相同。
  • 有 order by，但没指定范围：默认是 range between unbounded preceding and current row。

注意默认的是 range，不是 rows。在这个默认范围下，与当前行排序值相同的记录也会一起进入计算范围。MySQL 默认窗口帧规则

举个小例子：假设 A 在同一天有两笔销售，金额分别是 100 和 200，而且没有其他记录。如果写：

sum(amount) over (
    partition by employee
    order by sale_date
)

两行的结果都会是 300，因为它们的排序值 sale_date 相同。

如果希望按照 id 区分先后，一笔一笔累加，得到 100、300，就使用前面完整的写法：

sum(amount) over (
    partition by employee
    order by sale_date, id
    rows between unbounded preceding and current row
)

所以练习逐行累计时，我会先把范围明确写出来，避免默认规则悄悄改变结果。

回到题目，按三个问题拆解
#

例如题目要求：“计算每名员工按时间排列的最近三笔销售金额之和。”

题意 对应写法
每名员工分别计算 partition by employee
按时间排列，同一天按 id 排列 order by sale_date, id
最近三笔，包含当前这笔 rows between 2 preceding and current row
金额之和 sum(amount)

组合起来就是：

sum(amount) over (
    partition by employee
    order by sale_date, id
    rows between 2 preceding and current row
)

这一节先记住：函数决定“算什么”，partition by 决定“和谁一起算”，order by 决定“按什么顺序”，窗口范围决定“当前取哪些行”。 再遇到长长的 over (...)，就可以逐层拆开看了。 p
